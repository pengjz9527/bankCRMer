# AI营销展业助手（易会办）—— 面谈中场景深度分析

> 两个关键问题：
> 1. 客户不按剧本走怎么办？→ 实时决策辅助
> 2. 客户经理和客户一起看APP时怎么办？→ 双视角设计

---

## 问题一：客户不按剧本走——"偏离场景预制 + 点选即得"设计

### 1.1 核心设计思想

**核心矛盾**：面谈中客户一句话就能让剧本作废，留给客户经理的响应时间只有2-5秒。

**设计答案**：不是"客户偏了再临时输入"，而是**在生成作战包时就把最可能的偏离场景预制好**。客户经理看到客户偏离，只需点选命中场景 → 立即获得应对话术和调整方案，0等待。

```
          访前作战包生成
                │
    ┌───────────┼───────────┐
    ▼           ▼           ▼
 主剧本      偏离场景预制   兜底策略
 (happy      (每个线索预判   (追问话术
  path)      3-5个分支)     兜底)
```

**核心理念对比：**

| | 旧思路（被动输入） | 新思路（偏离预制） |
|------|------|------|
| 客户偏离时 | 打字描述客户说的话 → 等AI响应（3-5秒） | 看一眼偏离选项 → 点选命中场景（<1秒） |
| 命中率 | 首次使用为0，每次靠AI实时生成 | 生成作战包时已预判，覆盖80%常见偏离 |
| 未命中时 | 降级到输入模式 | 点"兜底话术" → 追问引导 → 标记新场景事后补充 |
| 持续优化 | 每次都是新对话，无积累 | 未命中的偏离事后补充到预制库，越用越准 |

---

### 1.2 偏离场景预制的结构

每条营销线索在生成时，同步生成主路径 + 偏离分支树：

```
线索 #1：定存到期承接（主路径）
│
├── 主路径：客户接受 → 推荐产品 → 介绍卖点 → 确认意向
│
├── 偏离分支（预制3-5个）
│   ├── 分支A：「钱已经安排/转走了」
│   │   ├── 响应话术：先确认去向，再判断新机会
│   │   ├── 调整策略：根据去向切换推荐
│   │   └── 匹配产品：现金管理/短期/按揭等
│   │
│   ├── 分支B：「想要保本的/不能亏」
│   │   ├── 响应话术：确认风险底线
│   │   ├── 调整策略：切换为R1存款/现金管理
│   │   └── 匹配产品：大额存单/结构性存款/货币基金
│   │
│   ├── 分支C：「收益太低了」
│   │   ├── 响应话术：解释收益对比基准
│   │   ├── 调整策略：推更高收益产品（注意风测匹配）
│   │   └── 匹配产品：R3基金/悦享周期
│   │
│   ├── 分支D：「考虑一下/再说」
│   │   ├── 响应话术：不施压，约定后续跟进
│   │   ├── 调整策略：标记意向待跟进
│   │   └── 后续动作：创建X天后跟进任务
│   │
│   └── 分支E：「其他银行也有类似产品」
│       ├── 响应话术：差异化优势对比
│       ├── 调整策略：突出我行产品的独特卖点
│       └── 匹配产品：强调本行专属/费率优势
│
└── 未命中 → 兜底话术（追问引导 + 事后补充到预制库）
```

### 1.3 客户经理实际操作流程

```
客户经理按主剧本推进：
  "王先生，您25万定存快到期了，我帮您看了几款收益更好的理财..."
            ↓
客户偏离（举例："那个钱我已经转走了"）
            ↓
客户经理扫一眼屏幕下方的"偏离场景列表"：
            ↓
┌──────────────────────────────────┐
│ 💡 客户可能这样说：               │
│                                  │
│ ○ 钱已经安排/转走了    ← 命中！   │  ← 一眼扫到，点选
│ ○ 想要保本的                     │
│ ○ 收益太低了                     │
│ ○ 考虑一下/再说                  │
│ ○ 其他银行也有类似产品            │
│ ○ 以上都不匹配 → 兜底话术        │
│ ○ 输入客户原话 → 智能搜索        │  ← 兜底方案
└──────────────────────────────────┘
            ↓ 点击"钱已经安排/转走了"
┌──────────────────────────────────┐
│ 📍 偏离: 钱已转走                 │
│                                  │
│ 💬 应对话术：                     │
│ "了解了王先生，方便问一下这笔钱   │
│  是用于什么方面吗？买房还是投资   │
│  还是其他用途？说不定我这边也能   │
│  帮上忙。"                       │
│                          [复制]  │
│                                  │
│ 🎯 策略调整：                    │
│ · 先追问资金去向，不要急于推销    │
│ · 如果是买房 → 推按揭/短期灵活   │
│ · 如果是投资 → 对比我行产品优势  │
│ · 如果是转他行 → 了解原因        │
│                                  │
│ 📦 备选产品（根据去向动态调整）    │
│ ┌──────┐ ┌──────┐ ┌──────┐    │
│ │现金管│ │短期理│ │按揭贷│    │
│ │R1    │ │R2    │ │  —   │    │
│ └──────┘ └──────┘ └──────┘    │
│                                  │
│ [返回剧本]  [切换到新线索]        │
└──────────────────────────────────┘
```

**关键设计点**：
- 偏离场景列表是**嵌入式**的，不遮挡主界面，客户经理一眼能扫到
- **点选即得**，不需要打字，不需要等待
- 提供了"返回剧本"路径，如果客户只是随口一说，可以拉回来继续

### 1.4 偏离场景的分类与预制规则

每条营销线索的偏离场景，由AI在生成作战包时根据以下经验规则自动预判：

| 偏离类型 | 触发场景示例 | 预制规则 |
|------|------|------|
| **拒绝型** | "不需要""已经有了""不感兴趣" | 通用拒绝应对话术 + 追问原因 |
| **比较型** | "别的银行也有""支付宝也能买" | 差异化优势话术 + 本行专属产品 |
| **条件型** | "收益太低""期限太长""门槛太高" | 条件调整 → 匹配替代产品 |
| **拖延型** | "考虑一下""回去跟家人商量" | 不施压话术 + 创建跟进任务 |
| **状况变更型** | "钱已转走""最近缺钱""换工作了" | 追问新状况 → 重新匹配需求 |
| **异议型** | "理财会亏吧""保险都是骗人的" | 知识解释 + 数据说明 + 案例 |

> 这些规则随着使用积累会不断丰富，形成该客户经理/该分行的"偏离场景经验库"。

### 1.5 未命中场景的处理与学习闭环

当所有预制偏离都不匹配时：

```
客户说出完全在预制列表外的话
        ↓
客户经理点击「以上都不匹配 → 兜底话术」
        ↓
┌──────────────────────────────────┐
│ 💬 兜底话术                       │
│                                  │
│ "王先生，您说的这个情况我了解了，  │
│  方便详细跟我说说吗？我看看怎么帮  │
│  您规划更好。"                    │
│                          [复制]  │
│                                  │
│ 📌 追问方向：                    │
│ · 发生了什么变化？               │
│ · 您现在最关心的是什么？          │
│ · 有什么我可以帮您解决的？        │
│                                  │
│ [输入客户原话 → 实时搜索]  ← 备选  │
└──────────────────────────────────┘
        ↓
面谈结束后，APP自动弹出：
┌──────────────────────────────────┐
│ 📝 补充偏离场景                    │
│                                  │
│ 本次面谈中，客户说了预制列表外的   │
│ 话，建议补充为新偏离场景：          │
│                                  │
│ 线索：定存到期承接                 │
│ 客户原话：[待填写]                │
│ 你是如何应对的：[待填写]           │
│                                  │
│ [保存为新的偏离分支]  [跳过]       │
│                                  │
│ 保存后将用于后续作战包的预制      │
└──────────────────────────────────┘
```

**学习闭环**：
```
面谈中未命中 → 兜底话术过渡 → 面谈后补充记录 → 纳入预制库 → 下次作战包自动包含
```

### 1.6 偏离场景预制的生成时机与来源

| 来源 | 说明 | 优先级 |
|------|------|:---:|
| **系统经验库** | AI基于金融营销常见异议场景预生成的通用偏离分支 | 基础层 |
| **该客户历史偏离** | 该客户历次面谈中出现过的偏离场景（如"上次就说过不喜欢保险"） | 增强层 |
| **该客户经理经验** | 该客户经理过去标记的偏离场景（个性化经验积累） | 个性化层 |
| **本分行常见偏离** | 同分行其他客户经理标记的高频偏离（地域化特征，如"我们这边都买房子"） | 地域层 |

生成规则：
- 系统经验库 = 必须有（每条线索至少3个偏离分支）
- 该客户历史偏离 = 有则叠加（最多追加2个）
- 个性化+地域 = 有则叠加（最多追加2个）
- 总偏离分支控制在5-7个，超出则按优先级截断

### 1.7 完整面谈中的剧本+偏离交互模型

```
┌──────────────────────────────────────────┐
│          面谈界面（私密模式）               │
├──────────────────────────────────────────┤
│                                          │

│  │ [XX理财 3.8%] [YY悦享 4.1%] [ZZ 2.5%]│  │
│  └────────────────────────────────────┘  │

│  ── 客户可能偏离 ────────────────────    │  ← 偏离预制区

│  │                                    │  │

│  │ ○ 想要保本的                       │  │
│  │ ○ 收益太低了                       │  │
│  │ ○ 考虑一下/再说                    │  │
│  │ ○ 其他银行也有类似产品              │  │
│  │ ───────────────────────────       │  │
│  │ ○ 以上都不匹配 → 兜底话术          │  │
│  │                                    │  │
│  └────────────────────────────────────┘  │
│                                          │
├──────────────────────────────────────────┤
│ [🔒私密]  [👁展示]  [📝记录]  [结束面谈]  │
└──────────────────────────────────────────┘
```

**操作流程**：
1. 客户经理按照"主剧本区"的话术推进
2. 客户如果正常回应 → 继续展示推荐产品，可切换到[展示模式]给客户看
3. 客户如果偏离 → 扫一眼底部的"偏离预制区"，点选命中的分支 → 展开应对话术和调整策略
4. 偏离处理完后 → 可选择"返回剧本"继续当前线索，或"切换到新线索"调整议程
5. 所有预制都不匹配 → 点"兜底话术"，面谈后补充

### 1.8 设计原则总结

| 原则 | 说明 |
|------|------|
| **预制而非临场** | 作战包生成时就把偏离分支预判好，面谈中不需要打字等响应 |
| **点选而非输入** | 客户经理只需从5-7个选项中点选，<1秒即可获得应对话术 |
| **分层预制** | 系统通用 + 客户历史 + 个人经验 + 地域特征，四层叠加 |
| **兜底不尬** | 全部未命中时，兜底话术以追问引导过渡，保持对话流畅 |
| **闭环学习** | 未命中的偏离面谈后补充，下次自动纳入预制，越用越准 |
| **渐进增强** | 一期可以先只有"系统经验库"(通用偏离分支)；后续迭代加入个性化和地域层 |

## 问题二：客户经理和客户一起看APP——"双视角"设计

### 2.1 问题的本质

当客户经理向客户展示产品时，存在两类信息：

```
              客户经理需要看                  客户可以看
              ─────────────                  ─────────
              · 产品详情                      · 产品核心卖点
              · 收益率/风险                   · 收益率/风险
              · 推荐理由（内部话术）            · 产品对比
              · 客户匹配度分析                · 最近业绩走势
              · 合规提示（不能给客户看）        · 购买规则
              · 客户的资产/偏好数据            ✗ 内部策略/话术
              · 下一步策略建议                ✗ 客户隐私数据
              · 转介绍提醒                    ✗ 合规红线提示
              · ...                          ✗ 其他客户的数据
              ─────────────                  ─────────
                  私密层                         可见层
```

**核心问题**：同一个APP界面，客户经理和客户看到的内容应该不同。

### 2.2 设计答案：一个界面，两种模式

```
┌──────────────────────────────────────────┐
│            同一个产品详情页                 │
│                                          │
│  ┌── 私密模式（客户经理自己看）──────┐    │
│  │                                   │    │
│  │  产品名称 · R2稳健                 │    │
│  │  ┌──────┬──────┬──────┬──────┐   │    │
│  │  │ 3.8% │ 1万  │ 标签  │ R2  │   │    │
│  │  └──────┴──────┴──────┴──────┘   │    │
│  │                                   │    │
│  │  📊 推荐理由：匹配客户稳健偏好...    │    │ ← 私密
│  │  🎯 营销策略：先讲收益再讲风险...    │    │ ← 私密
│  │  💬 介绍话术："这款产品最大特点是..│    │ ← 私密
│  │  ⚠ 合规提醒：必须说明非保本...      │    │ ← 私密
│  │                                   │    │
│  └───────────────────────────────────┘    │
│                                          │
│  ┌── 展示模式（给客户看）──────────┐    │
│  │                                   │    │
│  │          XX稳健增长A              │    │
│  │          中低风险 · R2            │    │
│  │                                   │    │
│  │         ┌───────────┐            │    │
│  │         │           │            │    │
│  │         │  走势图    │            │    │
│  │         │           │            │    │
│  │         └───────────┘            │    │
│  │                                   │    │
│  │  近半年年化          3.8%         │    │
│  │  起购金额          10,000元        │    │
│  │  风险等级              R2          │    │
│  │                                   │    │
│  │  ✔ 成立3年 · 历史业绩稳定          │    │
│  │  ✔ 每月可赎回 · 流动性好           │    │
│  │  ✔ 低风险等级 · 适合稳健投资者     │    │
│  │                                   │    │
│  └───────────────────────────────────┘    │
│                                          │
│         [🔒 私密模式]  [👁 展示模式]        │
└──────────────────────────────────────────┘
```

### 2.3 两种模式的切换设计

```
┌──────────────────────────────────────┐
│ 状态一：私密模式（默认）               │
│                                      │
│ · 客户经理自己看，手机屏幕朝自己       │
│ · 完整信息：数据、策略、话术、合规     │
│ · 界面：信息密度高，有内部标签和提示    │
│ · 底部浮动按钮：[👁 切换展示模式]      │
│                                      │
├──────────────────────────────────────┤
│ 状态二：展示模式                       │
│                                      │
│ · 客户经理把屏幕转向客户               │
│ · 精简信息：只展示客户应该看到的内容    │
│ · 界面：字号加大、信息精简、品牌感强    │
│ · 底部浮动按钮：[🔒 切回私密模式]      │
│ · 顶部有提示条："当前为展示模式"       │
│                                      │
└──────────────────────────────────────┘
```

**切换触发方式**：
- 点击底部浮动按钮切换（推荐）
- 双击屏幕空白区切换（备选，更隐蔽）
- 横屏自动切换为展示模式（备选，利用设备姿态）

### 2.4 展示模式 vs 私密模式的设计差异

| 维度 | 私密模式 | 展示模式 |
|------|---------|---------|
| **信息层级** | 完整（策略+话术+产品+合规） | 仅产品核心信息 |
| **字号** | 标准（适合自己阅读） | 偏大（适合两人一起看） |
| **图表** | 详细走势图、多维度数据 | 简化的关键趋势图 |
| **标签** | 内部标签（推荐理由、匹配度） | 客户友好的卖点标签 |
| **话术** | 显示（可复制） | 隐藏 |
| **合规提示** | 显示（红色警告） | 隐藏 |
| **配色** | 信息功能配色 | 品牌感、专业感 |
| **头像/姓名** | 显示客户姓名 | 隐藏客户个人信息 |
| **顶部** | 正常标题栏 | "展示模式"提示条 |
| **数据口径** | 精确数字 | 可适当模糊（如"约3.8%"） |

### 2.6 "展示模式"的配套交互细节

**1. 翻转即展示**
- 客户经理把手机横屏或点击按钮 → APP进入展示模式
- 顶部出现"展示模式"提示条（绿色），提醒客户经理当前状态
- 再次点击或竖屏 → 回到私密模式

**2. 展示模式下禁止的操作**
- 禁止显示客户个人信息（姓名/手机号/资产等出现在页面上）
- 禁止显示内部策略和话术
- 禁止显示合规红线提示（"必须说明非保本"这类文字不能让客户看到）

**3. 展示模式下强化的操作**
- 字号调大（至少比私密模式大一号）
- 关键数字放大显示（收益率、风险等级）
- 走势图简化，去掉冗余标注
- 卖点用打勾/星星等可视化符号

**4. 安全兜底**
- 进入展示模式前，弹窗确认："切换到展示模式？部分内部信息将被隐藏"
- 展示模式下如果客户经理截图，系统自动替换为展示模式截图（不含内部信息）
- 如果检测到其他应用在前台（如微信），自动退出展示模式

### 2.7 关键设计决策

**Q: 是否应该有两个独立的APP界面（一个是客户经理端，一个是客户端）？**

**A: 不推荐**。原因：
1. 客户经理需要在两种模式间频繁切换（查一下内部信息 → 再给客户看 → 再查一下）
2. 两个独立界面增加操作成本（切换APP/切换页面 vs 一键切换模式）
3. 客户经理用同一个设备（手机/平板），物理上只有一个屏幕

**推荐方案**：同一页面，一键切换"私密/展示"两种渲染模式。

**Q: 展示模式用横屏还是竖屏？**

**A: 推荐横屏**。原因：
1. 横屏更适合两人并排观看（产品对比左右排列更自然）
2. 横屏暗示"这不是正常操作模式"，更容易区分
3. 横屏与竖屏的切换天然形成"模式切换"的心智模型

也可以给客户经理选择权：点击按钮切换内容（私密↔展示），旋转设备切换方向（竖↔横）。

## 总结：两个关键问题的设计原则

### 问题一：客户偏离剧本 → "偏离场景预制"

```
核心原则：预制而非临场 + 点选而非输入 + 兜底不尬 + 闭环学习

设计：
  作战包生成时 → 每条线索预判3-5个最可能偏离分支
  面谈中偏离时  → 客户经理扫一眼偏离列表 → 点选命中场景 → <1秒获得应对话术
  全部未命中    → 兜底话术（追问引导）→ 面谈后补充为新预制分支 → 下次自动包含

预制规则：
  系统经验库（通用）+ 客户历史偏离 + 客户经理个人经验 + 分行地域特征
  四层叠加，总数控制在5-7个，超出按优先级截断

卡片结构：应对话术 + 策略调整 + 备选产品 + [返回剧本]/[切换新线索]
```

### 问题二：一起看APP → "双视角模式"

```
核心原则：一个页面，两种模式，一键切换

私密模式 = 客户经理自己看（完整信息、策略、话术、合规、客户隐私数据）
展示模式 = 给客户看（精简信息、大字号、品牌感、无内部内容、无客户隐私）

切换方式：底部浮动按钮 [🔒私密] ↔ [👁展示]
安全保障：展示模式自动隐藏策略/话术/合规提示/客户个人信息
```

# 易会办 — 核心业务设计模型：待办 · 商机 · 作战包

> **定位**：本文档定义易会办最核心的业务对象（待办、商机、作战包、渠道执行计划）及其相互关系。所有后续需求设计、交互流程、数据模型必须遵循本文档确立的概念边界和生成链路。
>
> **版本**：v2.0  
> **最后更新**：2026-07-28

---

## 一、核心对象定义

### 1.1 待办 `Task`

**本质**：执行动作。客户经理每天需要完成的工作项，是日程管理的基本单元。

| 类型 | 标识 | 来源 | 示例 | 是否关联商机 | 是否携带作战包 |
|------|:---:|------|------|:---:|:---:|
| **普通待办** | — | 系统推送 | 产品到期、大额异动、贷款逾期、生日提醒、联络超期、信用卡待办 | ❌ | ❌ 可选 |
| **商机待办** | 🟣 | 商机生成 | 拜访客户·赵明辉（代发到账）、拜访客户·王建国（理财配置） | ✅ 必关联 | ✅ 必携带 |

**普通待办**：包含事务性工作（生日提醒、信用卡通知）和触达类工作（联络超期）。统归为"普通待办"，处理即结束，不产生商机回写。

**商机待办**：由商机生成作战包时强制创建。执行方式可以是电话拜访或线下面谈，完成后回写商机状态。

### 1.2 商机 `Opportunity`

**本质**：价值发现。可转化为 AUM 增长、产品销售的潜在客户需求，是考核目标的支撑。

| 属性 | 说明 |
|------|------|
| 状态流转 | 待跟进 → 已生成作战包 → 已触达 → 已转化 / 已流失 |
| 与待办的关系 | 商机 ≠ 待办。商机是"机会"，待办是"行动" |
| 与作战包的关系 | 商机是作战包的**唯一生成源** |

### 1.3 作战包 `BattlePackage`

**本质**：执行弹药。客户经理联系客户前的信息准备和能力支撑，是商机待办的资源配置。

| 属性 | 说明 |
|------|------|
| 适用场景 | 电话拜访（轻量模式）、线下面谈（全功能模式） |
| 核心内容 | 客户速览、切入话术、推荐产品、风险提示/偏离预案 |
| 与商机的关系 | 一个商机只生成一个作战包（1:1） |
| 与待办的关系 | 作战包不单独产生待办，它附着于商机待办 |

> ⚠️ **关键约束**：作战包不能凭空产生，必须源于商机。待办不能生成作战包，待办只能**携带**作战包。

### 1.4 渠道执行计划 `ChannelPlan`（v2.0 新增）

**本质**：执行路径。定义客户经理通过哪种渠道、以什么内容、用什么话术触达客户，是商机→待办的执行维度的具体化。

#### 1.4.1 五个触达渠道

| 渠道 | 标识 | 特性 | 适用内容 |
|------|:---:|------|---------|
| **短信** | `sms` | 自助渠道，投放→采集→分析→再投放闭环 | 到期提醒、生日祝福、工资入账、活动通知 |
| **手机银行 APP** | `app` | 自助渠道，栏位配置+个性化推送 | 权益投放、活动专区、产品推荐弹窗 |
| **企业微信** | `wecom` | 可交互渠道，文字/语音/图文/文件 | 产品推荐、图文方案、小程序卡片、实时对话 |
| **电话拜访** | `phone` | 可交互渠道，语音实时沟通 | 大额核实、到期承接、逾期催收、意向跟进 |
| **现场拜访** | `onsite` | 可交互渠道，面对面深度沟通 | 综合方案面谈、复杂产品讲解、高净值关怀 |

#### 1.4.2 ChannelPlan 结构

每个客户待办（CustomerTask）包含一个或多个渠道执行计划，每个计划描述一个渠道的工作安排：

```
ChannelPlan {
  channel:        "sms" | "wecom" | "phone" | "onsite" | "app"
  priority:       1-5                    // 该渠道在本待办中的优先级（1 最高）
  
  // 计划内容（按渠道类型不同）
  template_id:    string                 // 短信模板 ID（sms 渠道）
  template_content: string               // 预填充的短信内容（sms 渠道）
  script:         string                 // 话术/切入要点（phone/wecom/onsite 渠道）
  materials:      [string]               // 素材列表（wecom 渠道：图文/PDF/小程序卡片）
  agenda:         [string]               // 面谈议程（onsite 渠道）
  push_config:    object                 // 推送配置（app 渠道：栏位/客群/时间）
  
  // 状态追踪
  plan_status:    "pending" | "executed" | "skipped"
  executed_at:    string
}
```

#### 1.4.3 商机→渠道执行计划的生成规则

渠道执行计划由**信号类型**驱动，每个信号类型预设了渠道优先级矩阵（详见 §六 信号→渠道匹配策略）。生成时结合客户渠道可触达状态自动调整：被客户关闭的渠道自动降级，选择替代渠道。

### 1.5 客户渠道可触达配置 `CustomerChannel`（v2.0 新增）

**本质**：权限控制。记录每个客户每个渠道的签约/开通/关闭状态，作为渠道执行计划的**前置约束**。

| 状态 | 含义 | 该渠道是否可用于执行计划 |
|------|------|:--:|
| `active` | 已签约/已开通，可正常触达 | ✅ |
| `unsigned` | 未签约/未开通（如未加企微、未授权推送） | ❌（可引导开通） |
| `closed` | 客户明确关闭/退订/拉黑 | ❌（严禁使用） |

**状态变更触发器**：
- 客户退订短信 → `sms` → `closed`
- 客户拉黑企微 → `wecom` → `closed`
- 手机号码空号 → `phone` → `closed`
- 客户关闭 APP 推送 → `app` → `closed`
- 客户经理添加企微成功 → `wecom` → `active`
- 定期联络核实 → 更新 `verified_at`

> ⚠️ **关键约束**：生成渠道执行计划时，必须先查询 `customer_channels` 表，`closed` 渠道必须跳过，`unsigned` 渠道仅作为引导开通建议，不可直接使用。

## 二、核心关系：生成链路

```
                        商机（三来源之一）
                             │
                             ▼ [生成作战包]
                             │
                         作战包
                        （标准版）
                             │
                             ▼ 同步强制动作
                             │
                    创建商机待办 🟣
                     ├─ 标题："拜访客户 · XXX"
                     ├─ 方式：电话 或 线下面谈
                     ├─ 时段：AI 建议排程
                     ├─ 📋 携带作战包（可点击查看）
                     └─ 关联商机 ID（可追溯）
                             │
                             ▼
                    加入待办清单
                     → AI 日程排程预留时段
                             │
                             ▼
                      执行商机待办
                    ├─ 电话：打开作战包 → 拨号 → 沟通 → 完成
                    └─ 面谈：打开作战包 → P1→P2→...→P7 → 完成
                             │
                             ▼
                    回写商机状态
                  （已触达 / 已转化 / 需跟进）
```

## 三、商机的三种来源

### 来源一：系统推送商机

后台系统基于明确规则识别并自动推送，不依赖客户经理操作，不依赖大模型。

| 商机类型 | 推送系统 | 识别逻辑 | 关键字段 |
|------|------|------|------|
| 代发即将到账 | 数仓 → 代发流水 | 近 6 月有稳定代发 + 未来 7 天将到账 | 月均代发金额、预计到账日 |
| 流失预警 | 大数据平台 → 流失模型 | AUM 下降 + 活跃度衰减 + 他行转账 | 流失概率、资产余额、客户等级 |
| 产品到期（大额） | 数仓 → 持仓数据 | 到期金额 ≥ 阈值 | 产品名称、金额、到期日 |

> **特征**：规则明确、字段固定、不依赖大模型。本质是"条件筛选 + 阈值判断"。  
> **待扩展**：后续需细化补充可推送的商机类型清单。

### 来源二：客户经理主动创建

客户经理在执行普通待办、触达客户过程中，基于真实对话发现新需求后手动标记或创建。

**触发场景**：

| 触达方式 | 场景 | 商机示例 |
|------|------|------|
| 电话（产品到期） | 客户说"正好我也想看看理财" | "王建国·理财配置意向 · 25 万" |
| 电话（大额异动） | 入金客户透露"刚卖了套房" | "张丽华·卖房资金配置 · 300 万" |
| 生日问候闲聊 | 客户说"孩子要上大学了想存一笔" | "刘建国·教育金规划 · 20 万" |
| 线下面谈 | 偏离剧本 → 发现新需求 | "赵明辉·经营贷需求 · 50 万" |
| 联络超期重新触达 | 客户换了工作、升职加薪 | "陈晓燕·收入增长理财升级" |

**创建入口**：
- 处理普通待办时 → "标记为商机"
- 面谈中 P6 快速记录 → 标签 [新需求]
- 面谈结束 P7 → "补充偏离场景"
- 工作台 → 手动添加入口

> **特征**：基于真实对话确认、客户有明确意向或需求信号、转化概率最高。

### 来源三：AI 智能挖掘商机

AI 基于客户洞察、关系关联分析，结合大模型推理能力生成。**必须与来源一做严格区分**——如果只是规则筛选，不应归入此类。

| 能力 | 示例 | 为何需要大模型 |
|------|------|------|
| 客户生命阶段推断 | 分析消费流水 → 识别"子女升学""退休临近"节点 | 需语义理解消费摘要、归纳行为模式 |
| 关系图谱挖掘 | 同一企业代发客户 → 同事/上下级 → 转介绍可能 | 需跨客户实体关系推理 |
| 行为序列预测 | 近 3 月频繁浏览基金频道 + 无持仓 → 基金购买意向 | 需多源数据关联归纳 |
| 跨产品关联 | 经营贷客户 + 无理财持仓 + 经营流水稳定 → 闲置资金理财 | 需跨领域规则整合推理 |
| 竞品替代分析 | 他行转账摘要含"理财""定存" → 竞品到期/不满 → 替代推荐 | 需自然语言理解转账备注 |

> **特征**：非确定性、带置信度、有推理链路可解释。推送时需附带"为什么这么判断"，与来源一的"命中规则"明确区分。

## 四、待办清单结构

首页每日待办清单中，两类待办并存：

| | 普通待办 | 商机待办 🟣 |
|------|------|------|
| **来源** | 系统推送 | 商机生成 |
| **示例** | 产品到期、生日提醒、联络超期 | 拜访客户·赵明辉（代发到账） |
| **目的** | 处理即结束 | 转化价值 |
| **是否关联商机** | ❌ | ✅ 关联唯一商机 |
| **是否携带作战包** | ❌ | ✅ 必携带 |
| **执行方式** | 电话 / 微信 / 标记完成 | 电话拜访 / 线下面谈 |
| **完成后** | 无后续 | 回写商机状态 |
| **卡片视觉** | 普通任务卡 | 卡片带 📋 作战包标识 |

## 五、设计约束（强制遵循）

### 5.1 生成方向

```
✅ 允许的路径：
   商机 → 作战包 → 商机待办
   普通待办 → 标记为商机 → 商机 → 作战包 → 商机待办
   系统推送 → 商机 / 普通待办

❌ 禁止的路径：
   待办直接生成作战包（没有商机就没有作战包）
   作战包凭空创建（必须源于商机）
   面谈准备作为独立待办（面谈准备是"拜访客户"待办的组成部分）
```

### 5.2 数量约束

| 关系 | 约束 |
|------|------|
| 商机 : 作战包 | 1:1 |
| 作战包 : 商机待办 | 1:1 |
| 普通待办 : 作战包 | 0:0 或 0:1（可选携带） |

### 5.3 状态约束

| 场景 | 规则 |
|------|------|
| 商机已生成作战包 | 商机状态 → "已生成作战包，待触达" |
| 商机待办完成 | 商机状态 → "已触达，待结果" |
| 作战包过期未使用 | 商机状态回退 → "待跟进" |
| 普通待办完成 | 无回写，无后续 |

### 5.4 概念边界

- **待办 ≠ 商机**：待办是"事"，商机是"财"。不是每个待办都有商机，也不该是。
- **待办不产生作战包**：待办只能携带（配置）作战包，不能生成作战包。
- **商机待办 ≠ 面谈准备**：商机待办是"拜访客户"这个完整动作，面谈准备是它的一部分。
- **作战包不限于面谈**：电话拜访同样可以使用作战包（轻量模式），核心价值相同。

## 六、信号→渠道匹配策略（v2.0 新增）

### 6.1 策略概述

基于 15 种信号类型，每种信号预设了渠道优先级矩阵。一个信号可触发多个渠道响应，按优先级排列。**生成渠道执行计划时，需结合客户 `customer_channels` 表动态调整——已关闭的渠道跳过，选择下一优先级的替代渠道。**

### 6.2 信号-渠道匹配矩阵

| 信号类型 | P1(首选) | P2 | P3 | P4 | P5 |
|---------|:---:|:---:|:---:|:---:|:---:|
| due 产品到期 | phone | sms | wecom | onsite | app |
| overdue 贷款逾期 | phone | sms | wecom | onsite | — |
| big_move 大额异动 | phone | wecom | sms | — | — |
| salary_in 代发工资 | sms | wecom | app | phone | — |
| contact_lapse 联络超期 | phone | wecom | sms | onsite | — |
| birthday 生日 | sms | wecom | phone | app | — |
| low_aum 流失风险 | sms | wecom | app | phone | — |
| high_aum_idle 闲置 | phone | wecom | onsite | sms | — |
| fund_browse 基金浏览 | wecom | app | sms | phone | — |
| wealth_browse 理财浏览 | wecom | app | sms | phone | — |
| loan_browse 信贷浏览 | wecom | app | phone | sms | — |
| insurance_browse 保险浏览 | wecom | phone | onsite | — | — |
| risk_retest 风评变更 | phone | wecom | onsite | app | — |
| insight_change 洞察变化 | phone | wecom | sms | — | — |
| insight_risk 洞察预警 | phone | wecom | sms | onsite | — |

### 6.3 规律总结

| 信号特性 | 首选渠道 | 理由 |
|----------|:---:|------|
| **紧急/高价值**（逾期、异动、预警） | phone | 即时性强，闭环快 |
| **信息通知型**（到期、生日、工资） | sms | 低成本、必达、可模板化 |
| **意向跟进型**（浏览类信号） | wecom | 可发链接+图文，交互方便 |
| **复杂方案型**（闲置、风评、保险） | phone → onsite | 需要详细讲解，不宜文字 |
| **批量运营型**（低AUM） | sms + app | 低成本广覆盖 |

## 七、渠道行动 PDCA 闭环（v2.0 新增）

### 7.1 PDCA 模型

每个渠道行动都必须遵循 **Plan → Do → Check → Act** 闭环，确保执行有记录、反馈有响应、策略有迭代。

```
┌───────────────┐     ┌──────────────┐     ┌──────────────────┐     ┌─────────────────┐
│  P — Plan     │ →  │  D — Do      │ →  │  C — Check       │ →  │  A — Act        │
│  计划          │     │  执行         │     │  客户反馈         │     │  后续行动         │
│               │     │              │     │                  │     │                 │
│ · 模板准备     │     │ · 发送/拨打   │     │ · 正面: 加速推进  │     │ · 下一动作       │
│ · 话术准备     │     │ · 拜访/投放   │     │ · 中性: 持续跟进  │     │ · 渠道切换       │
│ · 时机选择     │     │ · 记录快照    │     │ · 负面: 调整策略  │     │ · 时效设定       │
│ · 合规检查     │     │              │     │ · 无效: 切换渠道  │     │ · 信息更新       │
└───────────────┘     └──────────────┘     └──────────────────┘     └─────────────────┘
```

### 7.2 各渠道反馈选项

#### 短信渠道

| 反馈选项 | 含义 | 后续行动 | 时效 |
|----------|------|----------|------|
| `delivered` 已送达 | 平台返回送达成功 | 3天后企微/电话跟进 | +3d |
| `failed` 发送失败 | 号码无效/空号 | **标记 sms=closed**，切换电话 | 当天 |
| `clicked` 点击链接 | 客户点击短信链接 | 企微发送详细资料 | +1d |
| `replied_positive` 正面回复 | 「好的」「收到」 | 立即电话跟进 | 当天 |
| `replied_inquiry` 咨询回复 | 「怎么办理？」 | 1h内电话/企微回复 | 1h内 |
| `replied_negative` 拒绝回复 | 「不需要」 | 记录拒绝原因，30天冷却 | +0d |
| `unsubscribed` 退订 | 回复T退订 | **标记 sms=closed** | 当天 |
| `no_response` 无响应 | 72h无任何反馈 | 7天后换渠道再触达 | +7d |

#### 企业微信渠道

| 反馈选项 | 含义 | 后续行动 | 时效 |
|----------|------|----------|------|
| `delivered_unread` 已送达未读 | 消息未查看 | 2天后电话提醒 | +2d |
| `read` 已读 | 客户已查看 | 追加详细资料，开启对话 | +1d |
| `replied_interested` 有兴趣 | 「发给我看看」 | **立即深度沟通**→预约→作战包 | 当天 |
| `replied_inquiry` 咨询 | 深入询问细节 | 1h内专业解答→挖掘需求 | 1h内 |
| `replied_reject` 拒绝 | 「不考虑」 | 记录原因，30天后换策略 | +0d |

### 7.3 PDCA 关键原则

| 原则 | 说明 |
|------|------|
| **渠道闭环** | 每个渠道的反馈→行动链完整，不会"发了就完了" |
| **渠道可切换** | 一个渠道失败/关闭 → 自动选择替代渠道 |
| **时效分级** | 紧急（逾期/异动/投诉）1h内；重要 1天内；一般 3-7天；低优 30天+ |
| **负面反馈保护** | 拒绝/退订/拉黑后设定冷却期，避免骚扰客户 |
| **正向反馈放大** | 有兴趣/新需求立即跟进，抓住营销窗口期 |
| **信息实时更新** | 空号/拉黑/退订等立即更新 `customer_channels` 状态 |

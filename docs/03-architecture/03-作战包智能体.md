# BattlePkgAgent · 作战包生成智能体设计方案

> **版本**：v1.0 | **日期**：2026-07-24 | **状态**：✅ 已实现

---

## 一、业务诉求

### 1.1 核心痛点

银行客户经理在每次客户接触（电话或面谈）前需要做大量准备工作：
- 了解客户基本情况（资产规模、风险偏好、持仓结构）
- 发现营销切入点（客户有什么需求、有哪些信号）
- 准备话术（怎么开口、怎么引导、怎么应对话术偏离）
- 匹配产品（推荐什么产品、为什么推荐）
- 识别风险（合规风险、客户关系风险）

传统做法中，这些工作需要客户经理手工翻阅多个系统，耗时长且质量参差不齐。

### 1.2 核心价值

| 模块 | 输入 | AI 产出 | 客户经理获益 |
|------|------|--------|------------|
| **客户速览** | 客户全维度数据 | 一句话定位 + 3-5句画像摘要 + 拜访目的 | 30 秒了解客户全貌 |
| **营销线索** | 客户数据 + 商机信号 | 发现依据→策略→话术→产品→偏离应对 完整链路 | 照着念就能完成高质量拜访 |
| **产品推荐** | 产品库 + 客户画像 | 规则初筛（AUM/风测/场景标签）+ AI 精选 | 免去翻产品手册 |
| **风险提示** | 贷款/沟通记录/AUM变化 | 合规风险 + 关系风险 | 避免踩红线 |
| **访后动作** | 拜访结果 | 跟进建议清单 | 形成闭环 |

### 1.3 业务场景

| 场景 | 触发方 | 模式 | 说明 |
|------|:---:|------|------|
| **标准版作战包** | 客户经理 | 统一 | 2-4 条线索，含面谈议程/偏离应对分支/产品话术 |
| **商机关联** | OppMiningAgent | 上游输入 | 作战包带上商机信号信息，精准切入 |

## 二、流程设计

### 2.1 作战包生成流程

```
客户经理点击"生成作战包"
  │
  ├─→ POST /api/battle-packages/generate    (同步)
  │     { "opp_id": "OPP_AI_23_xxx", "mode": "标准版" }
  │     （当前使用标准版实现）
  │
  │  或直接调用 Agent:
  │    battle_pkg_agent.generate_battle_package(ctx, cust_id, mode)
  │
  ├─→ Step 1: 加载客户数据
  │     _build_customer_context(cust_id) → 全维度客户上下文
  │     包含: customer, family, holdings, transactions,
  │           behavior_logs, communications, risk, relations,
  │           loans, benefits, activities
  │
  ├─→ Step 2: 规则产品初筛
  │     select_products_for_customer()
  │     ├── 风测→风险等级映射（R1→仅R1, R3→R1-R3, ...）
  │     ├── AUM→场景标签匹配（<5万→活钱管理, >50万→高收益）
  │     ├── 历史持仓偏好加分（持有过理财→理财类加分）
  │     ├── 门槛匹配（起购金额 ≤ AUM/10）
  │     └── 返回 top 6 产品
  │
  ├─→ Step 3: 构建 LLM User Prompt
  │     _build_user_prompt(cust_id, mode, opp_info)
  │     ├── 客户数据 JSON 格式化
  │     ├── 产品库上下文注入（预筛选的产品列表）
  │     ├── 商机信息注入（如有）
  │     └── 洞察快照注入（如有 CustomerInsightAgent 缓存）
  │
  ├─→ Step 4: LLM 生成
  │     adapter.analyze_json(system_prompt, user_prompt)
  │     model: deepseek-chat, temperature: 0.4
  │     返回: { customer_overview, agenda, clues, risk_warnings, ... }
  │
  ├─→ Step 5: 持久化
  │     save_battle_package() → battle_packages 表 + battle_package_clues 表
  │     bp_id = "BP_AI_{timestamp}"
  │     有效期 7 天
  │
  └─→ 返回结果 → 前端渲染作战包预览
```

### 2.2 产品匹配规则

```
select_products_for_customer(customer, product_db, risk_result="稳健型", max=6)
  │
  ├─→ 1. 风险等级过滤
  │     risk_map = { "保守型":["R1"], "稳健型":["R1","R2"],
  │                   "平衡型":["R1","R2","R3"], ... }
  │     只保留 risk_level ∈ allowed_risks 的产品
  │
  ├─→ 2. 状态过滤
  │     只保留 status = "在售" 的产品
  │
  ├─→ 3. 多因子打分
  │     ├─ AUM 场景匹配: AUM<5万+活钱管理 +10, >10万+稳健投资 +8, >50万+高收益 +6
  │     ├─ 保本保息+保守型: +10
  │     ├─ 历史持仓同类型: +5/类
  │     ├─ 门槛匹配: 起购≤1万 且 AUM>门槛×10: +3
  │     └─ 收益率: expected_return_max>3%: +3
  │
  └─→ 4. 排序 → 返回 top 6
```

### 2.3 洞察快照接管机制

```
作战包生成时检查 CustomerInsightAgent 缓存:

if insight_data && insight_data.overview:
    将 overview 直接注入 user_prompt
    提示 LLM: "customer_overview 请直接使用上面提供的洞察快照，不要重新生成"
else:
    LLM 自行生成 customer_overview（基于原始数据）

优势: 避免反复调用 LLM 生成重复的客户速览，降低延迟和成本
```


### 3.2 核心类结构

```
BattlePackageAgent (extends Agent)
├── system_prompt: "prompts/battle_package.md"
├── product_db: prototype/data/product_database.json (64 款产品)
│
├── generate_battle_package(ctx, cust_id, mode, opp_info, insight_data, progress_cb)
│   ├── _build_customer_context(cust_id)     # 组装客户全维度数据
│   ├── select_products_for_customer()       # 规则初筛产品
│   ├── format_product_context()             # 产品库格式化
│   ├── _build_user_prompt()                 # 构建 LLM prompt
│   ├── adapter.analyze_json()               # LLM 生成
│   └── 返回 bp_data dict
│
├── save_battle_package(bp_result, db, opp_id)
│   ├── INSERT INTO battle_packages         # 主表
│   └── INSERT INTO battle_package_clues    # 线索子表
│
└── select_products_for_customer(customer, product_db, risk_result)
    ├── 风险过滤 + 状态过滤
    ├── 场景标签/历史偏好/门槛/收益率 多因子打分
    └── 排序返回 top 6
```

### 3.3 Prompt 设计

System Prompt（`prompts/battle_package.md`, 118 行）：

```
一、角色定位
  - 银行客户经理的"访前作战包生成专家"
  - 根据客户全维度数据生成可即用的作战包

二、核心能力
  1. 客户速览生成
  2. 营销线索编排（发现依据→策略→话术→产品→偏离应对）
  3. 产品智能匹配
  4. 风险提示生成
  5. 访后动作建议

三、输出规范（JSON Schema）
  - customer_overview / agenda / clues / benefit_entries / risk_warnings / post_visit_actions

四、营销线索逻辑链要求
  发现依据 → 营销策略 → 切入话术 → 产品列表 → 产品话术

五、产品匹配规则
  - 风险等级、资金状况、行为偏好 → 产品推荐

六、标准版特征
  - 标准版: 2-4条线索, 全文议程, 含偏离应对, 话术详细

七、营销切入点生成规则
  - 权益/活动/备用hook
  - 话术必须以客户真实姓氏+正确称呼开头

八、风险提示要求
  - 合规风险 + 关系风险
```

### 3.4 产品数据库

```
数据源: prototype/data/product_database.json (64 款产品)
字段: product_name, category, sub_category, risk_level,
      min_amount, term_desc, expected_return_min/max,
      scenario_tags, selling_points, status
```

### 4.3 Agent 间协作

```
                    CustomerInsightAgent
                           │
                           │ get_customer_overview(cust_id)
                           ▼
OppMiningAgent ──→ BattlePkgAgent ←── Product DB (JSON)
  (商机信号)          (生成作战包)         (产品匹配)
                           │
                           ▼
                   battle_packages 表
                   battle_package_clues 表
                           │
                           ▼
                   前端作战包预览页面
                   (workbench.html)
```

### 4.4 数据库存储

```
battle_packages 表:
  bp_id, opp_id, cust_id, mode, status,
  customer_overview (JSON), agenda (JSON),
  risk_warnings (JSON), post_visit_actions (JSON),
  generated_at, expires_at (7天有效期)

battle_package_clues 表:
  clue_id, bp_id, priority, title,
  discovery_basis, strategy, opening_script,
  products (JSON), deviation_branches (JSON)
```

## 五、配置与运行

### Agent 元数据

```python
@agent(
    name="作战包生成智能体",
    role="battle_package_maker",
    model="deepseek-chat",
    triggers=["on_demand"],     # 仅按需触发（实时生成）
    rate_limit=20,              # 每分钟最多 20 次
    timeout=300,                # 5 分钟超时
)
```

### 初始化

```python
from agentos.agents.battle_package import create_battle_pkg_agent
battle_pkg_agent = create_battle_pkg_agent()
# → 自动注册到全局 harness
# → 自动加载 prompts/battle_package.md
# → 延迟加载 product_database.json
```

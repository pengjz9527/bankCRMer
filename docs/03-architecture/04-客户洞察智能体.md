# CustomerInsightAgent · 客户洞察智能体设计方案

> **版本**：v1.1 | **日期**：2026-07-27 | **状态**：已实现
>
> **v1.1 变更**：Agent 间协作新增 OppMiningAgent 作为洞察缓存消费者（方案 B+）

## 一、业务诉求

### 1.1 核心痛点

客户经理需要快速、全面地了解每一位管户，但原始数据分散在多个系统：
- 基本信息在客户系统、资产在理财系统、行为在 App 日志、沟通在 CRM
- 缺乏"30 秒速览"能力——每次拜访前需花 5-10 分钟翻阅多个页面
- 无法及时发现客户变化（比如 AUM 在悄悄下降、App 活跃度在萎缩）
- 风险预警滞后——等客户真的流失了才知道

### 1.2 核心价值

| 洞察能力 | 具体的输出 | 客户经理获益 |
|---------|-----------|------------|
| **360° 客户速览** | 基本信息 + 家庭生命周期标签 + 资产结构 + 收入模式 + 风险画像 + 活跃度 + 关系网络 | 30 秒了解客户全貌 |
| **变化信号监测** | 资金异动/行为突变/兴趣转移/等级变化/到期临近/关系断裂 | 发现"正在发生"的变化 |
| **风险预警评分** | 流失风险/降级风险/逾期风险/竞品转移/服务缺口 + 四色风险等级 | 主动干预而非被动应对 |
| **下游 Agent 共享** | get_customer_overview() 接口供 BattlePkgAgent 调用 | 避免重复 LLM 调用 |

### 1.3 业务场景

| 场景 | 触发方 | 频率 | 说明 |
|------|:---:|------|------|
| **定时批量生成** | 系统 | 每周一次 | 全量扫描，T+1 快照入库 |
| **单客户按需生成** | Agent 内部 | 实时 | 供作战包等下游消费 |
| **客户频道筛选** | 前端的洞察筛选 | 按需 | 下拉筛选：客户洞察/变化信号/预警信号 |
| **洞察快照查询** | 前端 | 随时 | 客户详情页展示最新洞察 |

## 二、流程设计

### 2.1 批量生成流程

```
┌─────────────────────────────────────────────────────────────┐
│          定时批量客户洞察生成（每周日凌晨 3:00）                  │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Step 1: 查询全量客户                                        │
│    query_customers(limit=10000) → N 位活跃客户               │
│                                                             │
│  Step 2: 分批处理（8 人/批）                                  │
│    for each batch in chunk(customers, 8):                   │
│      ↓                                                      │
│  Step 3: 组装完整上下文                                       │
│    每位客户 → query_customer_full() →                       │
│    {customer, family, holdings, transactions,               │
│     behavior_logs, communications, risk, relations,         │
│     loans, benefits, activities}                            │
│      ↓                                                      │
│  Step 4: 数据精简 → 发送 LLM                                  │
│    transactions 取 top15, behavior_logs 取 top10,            │
│    communications 取 top5, relations 取 top5                │
│      ↓                                                      │
│  Step 5: LLM 调用                                            │
│    model: deepseek-chat                                     │
│    system_prompt: customer_insight.md                        │
│    temperature: 0.3                                         │
│      ↓                                                      │
│  Step 6: 入库                                                │
│    INSERT INTO customer_insights                              │
│    (cust_id, manager_id, overview_json,                      │
│     change_signals_json, risk_signals_json,                  │
│     risk_level, generated_at, expires_at)                    │
│    有效期 7 天                                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 单客户生成流程

```
BattlePkgAgent 或其他下游 Agent 调用:
  generate_single(ctx, cust_id)
    │
    ├─→ query_customer_full(cust_id)              # 全维度数据
    ├─→ _build_user_prompt([full], ctx)           # 构建单客户 prompt
    ├─→ adapter.analyze_json()                    # LLM 生成
    └─→ 返回 { overview, change_signals, risk_signals, risk_level, ... }
```

### 2.3 洞察缓存共享机制

```
CustomerInsightAgent ──(定时生成)──→ customer_insights 表
                                          │
                                          │ get_customer_overview(cust_id)
                                          ▼
                                    BattlePkgAgent
                                    (如洞察已缓存，直接注入 user_prompt
                                     跳过 LLM 重复生成 customer_overview)
```

### 2.4 关键设计决策

| 决策点 | 选择 | 理由 |
|-------|------|------|
| **存储策略** | T+1 快照入库 | 洞察不需要实时性，快照足够且成本可控 |
| **刷新频率** | 每周一次 | 客户画像变化缓慢，每周更新足够发现趋势 |
| **数据精简** | 交易取 top15, 行为取 top10 | 平衡 token 消耗与分析全面性 |
| **单客户生成** | 复用同一 prompt + 模型 | 避免为不同下游重复开发 |

### 3.2 风险评分规则

```
综合评分 = Σ(因子得分 × 权重)

因子权重:
  资金流出  25%  → high: 净流出>AUM×30%, medium: >AUM×10%
  行为衰减  20%  → high: 60天零登录, medium: 30天零登录
  等级下降  20%  → high: 已降级, medium: 临界
  产品到期  15%  → high: 30天内到期>AUM×50%, medium: 30天内有到期
  逾期记录  10%  → high: overdue≥3, medium: ≥1
  竞品行为  10%  → high: 浏览竞品+大额转出, medium: 浏览>5次

风险等级:
  red (≥70) → 橙色/红色预警，需立即干预
  orange (40-69) → 关注，近期可能恶化
  yellow (15-39) → 轻度关注，持续监测
  green (<15) → 健康
```

### 3.3 核心类结构

```
CustomerInsightAgent (extends Agent)
├── system_prompt: "prompts/customer_insight.md"
│
├── batch_generate_all(ctx, max_per_batch=8)    # 定时批量
│   ├── query_customers()
│   ├── chunk(8人/批)
│   ├── _analyze_batch()
│   └── _save_insight() × N
│
├── generate_single(ctx, cust_id)               # 单客户按需
│   ├── query_customer_full(cust_id)
│   ├── _build_user_prompt()
│   └── adapter.analyze_json()
│
├── get_customer_overview(cust_id)              # 供下游 Agent 调用
│   └── query_customer_insight(cust_id) → 返回最新快照
│
├── _analyze_batch(customers, ctx)              # 核心分析
│   ├── 组装全维度数据
│   ├── _build_user_prompt()
│   └── adapter.analyze_json(temperature=0.3)
│
└── _save_insight(result, manager_id)           # 持久化
    └── INSERT OR REPLACE INTO customer_insights
```

### 3.4 Prompt 设计

System Prompt（`prompts/customer_insight.md`, 197 行）：

```
一、角色定位
  - 360°客户洞察专家
  - 产出三大类洞察：客户速览、变化信号、风险预警

二、输入数据
  - 12 个数据域完整说明（customer/family/business/holdings/
    transactions/loans/behavior_logs/communications/
    risk_assessment/relations/benefits/activities）

三、输出要求
  - overview（客户速览）: 8 个子模块
    basic / family_lifecycle / asset_structure / income_pattern /
    risk_profile / engagement / relationship_network / existing_opportunities
  - change_signals（变化信号）: 6 种类型，0-3条
    {"type","severity","title","detail","suggested_action"}
  - risk_signals（风险信号）: 5 种类型
    {"type","level","title","detail","suggested_action"}
  - 全局字段: risk_level, risk_score, generated_at

四、分析原则
  数据驱动、客户经理视角、简洁有力、风险可解释、
  家庭生命周期敏感
```

## 四、调用设计

### 4.1 API 端点

| 端点 | 方法 | 说明 |
|------|:---:|------|
| `/api/customer-insights/{cust_id}` | GET | 查询单客户最新洞察 |
| `/api/customer-insights/manager/{manager_id}` | GET | 查询某经理所有客户洞察列表 |
| `/api/customer-insights/filter` | GET | 按信号类型筛选客户（change/risk） |

### 4.2 核心 Skill 函数

```python
# 查询客户最新洞察快照
query_customer_insight(cust_id) → dict
# → 返回该客户最新一条洞察记录，含 overview/change_signals/risk_signals

# 查询经理所有客户洞察
query_customer_insights_by_manager(manager_id) → list[dict]
# → 每位客户最新洞察，附带 has_change/has_risk/change_count/risk_count

# 按洞察信号筛选客户
query_customers_by_insight_filter(manager_id, insight_filter)
# insight_filter='change' → 有变化信号的客户
# insight_filter='risk' → risk_level ∈ {orange, red} 的客户
```

### 4.3 Agent 间协作

```
CustomerInsightAgent
  │
  ├──(产出)─→ customer_insights 表（T+1 快照）
  │              │
  │              ├─→ 前端客户频道洞察筛选
  │              │   下拉选项: 客户洞察/变化信号/预警信号
  │              │
  │              ├─→ BattlePkgAgent.get_customer_overview(cust_id)
  │              │   作战包生成时复用洞察缓存
  │              │
  │              ├─→ OppMiningAgent._build_user_prompt()
  │              │   商机挖掘时注入 _insight_cache 进行交叉验证（方案 B+）
  │              │
  │              └─→ SchedulerAgent 日程排程
  │                  insight_alert 类型待办（洞察预警信号 → 排程）
  │
  └──(消费)←── query_customer_full()  # 从 AgentOS Skill 库获取原始数据
```

### 4.4 前端交互

```
客户频道 (W8):
  ┌─────────────────────────────────────────────┐
  │ 筛选: [客户洞察 ▾]  [搜索框]                  │
  │       ├─ 客户洞察（全部）                      │
  │       ├─ 变化信号（有行为变化信号）              │
  │       └─ 预警信号（有风险预警信号）              │
  ├─────────────────────────────────────────────┤
  │  客户列表（每行含风险等级标识）                  │
  │  🟢 张三  AUM 150万                           │
  │  🟠 李四  AUM 80万   ← 有变化信号             │
  │  🔴 王五  AUM 50万   ← 预警信号               │
  └─────────────────────────────────────────────┘

客户详情页: 展示最新洞察快照（overview + change_signals + risk_signals）
```

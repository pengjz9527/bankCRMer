## 一、业务诉求

### 1.1 核心痛点

银行客户经理每天面对大量碎片化信息：当日完成的客户触达、沟通记录、大额交易异动、产品变更、行内公告、外部金融要闻……信息分散在多个系统中，缺乏统一的汇总和提炼。

**问题**：
- 每日工作回顾靠手工记录或凭记忆，容易遗漏关键事项
- 金融资讯海量但缺乏筛选，客户经理没时间逐条阅读
- 周报/工作总结需要手动汇总，耗时且格式不一
- 面访后的口述内容需要手动整理录入

### 1.2 核心价值

| 能力 | 人工做 | AI 独特价值 |
|------|:---:|------|
| 昨日回顾 | 下班前花 10-15 分钟手动整理 | **30 秒自动生成**，结构化呈现 5 个维度 |
| 资讯摘要 | 浏览多个网站/APP，筛选阅读 | **自动抓取 + AI 提炼**，5-8 条精简要闻 |
| 周报汇总 | 每周末花 30-60 分钟汇总 | **自动聚合 7 天数据**，含统计与建议 |
| 面谈转写 | 凭记忆在 CRM 中录入关键信息 | **语音 → 文字 → PDCA**，自动提取并回填 |

### 1.3 角色定位

ContentAgent 是客户经理的「信息秘书」，定位为**前台 Agent**，聚焦**信息压缩与呈现**：

- **不参与**：后台管理决策、经营诊断、辅导建议
- **核心职责**：从繁杂数据中提炼关键信息，生成精炼、可读、有洞察的内容报告
- **协作关系**：
  - 从 `data_engine` 日增引擎获取产品变更/公告数据
  - 从 `news_fetcher` 获取金融资讯（Tushare/新浪财经）
  - 与 `SchedulerAgent` 互补：SchedulerAgent 做**排程**，ContentAgent 做**回顾**
  - 与 `QAAgent` 互补：QAAgent 做**问答**，ContentAgent 做**摘要**

## 二、流程设计

### 2.1 四项核心技能

```
ContentAgent（内容生成智能体）
  ├─→ gen_review      昨日回顾  ← 每日 20:00 定时
  ├─→ gen_digest      资讯摘要  ← 每日 08:35 定时
  ├─→ gen_summary     周报      ← 每周一 08:00 定时
  └─→ transcribe_dictation  面谈转写  ← 事件触发
```

### 2.2 gen_review（昨日回顾）流程

```
APScheduler 触发 (每日 20:00)
  │
  ├─→ scheduled_review_gen()
  │     │
  │     ├─→ 获取全行客户经理列表
  │     │     query: SELECT DISTINCT manager_id FROM cust_manager_rel
  │     │
  │     └─→ 对每位经理:
  │           │
  │           ├─→ _collect_review_data(mgr_id, yesterday)
  │           │     收集昨日 5 类数据:
  │           │     ├─ processing_records   (处理记录: task_type, cust_name, action)
  │           │     ├─ communications       (沟通记录: channel, summary, key_topics)
  │           │     ├─ transactions         (大额交易: amount > 30000)
  │           │     ├─ product_updates      (产品变更: change_type, old/new value)
  │           │     └─ internal_announcements (行内公告: ann_type, title)
  │           │
  │           ├─→ 数据为空? → 降级为规则生成
  │           │     _fallback_review() — 直接拼装，不走 LLM
  │           │
  │           ├─→ 数据非空 → LLM 生成
  │           │     adapter.analyze_json(
  │           │       system_prompt = prompts/content_agent.md
  │           │       user_prompt   = 结构化数据 JSON
  │           │       temperature   = 0.3
  │           │     )
  │           │     返回 JSON:
  │           │     { "date": "2026-07-29",
  │           │       "sections": [
  │           │         {"title":"今日概要", "content":"..."},
  │           │         {"title":"工作完成", "content":"..."},
  │           │         {"title":"客户动态", "content":"..."},
  │           │         {"title":"产品/公告", "content":"..."},
  │           │         {"title":"明日关注", "content":"..."}
  │           │       ]
  │           │     }
  │           │
  │           └─→ _save_review() → INSERT OR REPLACE INTO daily_reviews
  │
  └─→ 结果: 每位经理的昨日回顾存入 daily_reviews 表
```

### 2.3 gen_digest（资讯摘要）流程

```
APScheduler 触发 (每日 08:35，在 news_fetch 08:30 之后)
  │
  ├─→ scheduled_digest_gen()
  │     │
  │     ├─→ _collect_digest_data(today)
  │     │     从 daily_news 表读取当日资讯（最多 30 条）
  │     │     source: tushare / sina / eastmoney
  │     │
  │     ├─→ 无数据? → 返回 {"empty": true, "briefing": "暂无资讯"}
  │     │
  │     └─→ LLM 提炼
  │           → 筛选银行相关资讯（利率/理财/监管/房贷/基金/保险）
  │           → 生成 5-8 条要闻 (headlines)
  │           → 生成 50-100 字综合解读 (briefing)
  │           → 返回: {"headlines": [...], "briefing": "..."}
```

### 2.4 transcribe_dictation（面谈转写）流程

```
事件触发 (面访完成后)
  │
  ├─→ transcribe_dictation(audio_path / audio_bytes)
  │     │
  │     ├─→ Step 1: 阿里云 ASR 语音转文字
  │     │     AlibabaASRClient.transcribe()
  │     │     端点: nls-gateway-cn-shanghai.aliyuncs.com
  │     │     一句话识别 (≤60s)，支持本地文件和字节流
  │     │
  │     ├─→ Step 2: LLM 提取 PDCA + 画像变更 + 待办
  │     │     adapter.analyze_json(
  │     │       user_prompt = transcript 文本
  │     │       temperature = 0.2     (低温度确保稳定提取)
  │     │     )
  │     │     返回 JSON:
  │     │     {
  │     │       "transcript": "原始转写文本",
  │     │       "pdc": {"plan":"面谈目的","do":"执行情况",
  │     │               "check":"客户反馈","act":"后续动作"},
  │     │       "profile_changes": [
  │     │         {"field":"字段","old_value":"旧值",
  │     │          "new_value":"新值","confidence":"high"}
  │     │       ],
  │     │       "todos": [
  │     │         {"title":"待办","priority":"高","deadline":"2026-08-05"}
  │     │       ]
  │     │     }
  │     │
  │     └─→ 回填（由上层调用方完成）
  │           ├─→ meeting_records 表 (PDCA 字段)
  │           ├─→ profile_change_log 表 (画像变更，变更标红)
  │           └─→ 待办池 (生成后续待办)
```

### 2.5 降级策略

ContentAgent 的核心能力依赖 LLM，但设计了完善的降级方案：

| 场景 | 降级行为 |
|------|---------|
| **LLM 调用失败** | 规则引擎降级：`_fallback_review()` 直接拼装数据，不用 LLM |
| **昨日无数据** | 返回空回顾（各 section 标注"无记录"），仍然保存到 DB |
| **资讯源全部不可用** | 返回 `{"empty": true, "briefing": "暂无金融资讯"}` |
| **ASR 服务不可用** | 返回 `{"error": "语音转写失败: ..."}`,转录原文仍保留 |
| **知识库无匹配** | gen_digest 不依赖 RAG，直接基于抓取的资讯生成 |

## 三、数据模型

### 3.1 新表依赖

ContentAgent 依赖上一期「数据基础设施搭建」新建的 6 张表：

## 四、技术设计

### 4.1 Agent 注册

```python
# agentos/agents/content_agent.py
@agent(
    name="内容生成智能体",
    role="content_gen",
    description="信息秘书：生成昨日回顾/资讯摘要/周报/面谈口述转写",
    skills=[
        "gen_review", "gen_digest", "gen_summary",
        "transcribe_dictation",
    ],
    triggers=["scheduled", "on_demand", "event"],
    rate_limit=30,
    timeout=300,
)
class ContentAgent(Agent):
    system_prompt = "prompts/content_agent.md"
```

### 4.2 模型配置

| 决策点 | 选择 | 理由 |
|------|------|------|
| **模型** | 跟随全局 adapter 默认配置（当前 deepseek-v4-flash） | 摘要类任务无需强推理，优先保障低延迟 |
| **温度** | 0.3 (gen_review/gen_digest/gen_summary), 0.2 (transcribe_dictation) | 摘要需要适度创造性，转写需要稳定性 |
| **max_tokens** | 2048 (默认) | 回顾/摘要 300 字以内，高容错 |
| **输出格式** | JSON (analyze_json) | 结构化输出，便于解析和存储 |

### 4.3 定时任务注册

```python
# app.py — start_scheduler()
scheduler.add_job(scheduled_review_gen, "cron", hour=20, minute=0,  id="daily_review_gen")
scheduler.add_job(scheduled_digest_gen, "cron", hour=8,  minute=35, id="daily_digest_gen")
```

> **定时任务执行顺序**（每日）：
> - 07:30 数据日推进 → 08:00 日程排程 → 08:30 资讯抓取 → **08:35 资讯摘要** → **20:00 昨日回顾**

### 4.4 ASR 集成

面谈转写使用阿里云智能语音交互（NLS），通过官方 SDK `alibabacloud-nls-cloud-meta20180518` 获取 Token，调用 `nls-gateway-cn-shanghai.aliyuncs.com` 端点。

环境变量：`ALIBABA_ACCESS_KEY_ID` / `ALIBABA_ACCESS_KEY_SECRET` / `ALIBABA_NLS_APP_KEY`

设计决策：选阿里云而非腾讯云，因用户已有阿里云账号，准确率 97.5%，且面谈口述为自然语言无需金融专用模型。

## 六、设计决策

| 决策点 | 选择 | 备选方案 | 理由 |
|------|------|---------|------|
| **gen_review 数据源** | processing_records + communications + 大额交易 + 产品变更 + 公告 | 从 daily_schedules 解析 completed 任务 | 处理记录更精确反映实际完成情况 |
| **LLM 失败降级** | 规则引擎直接拼装（_fallback_review） | 抛异常 | 定时任务不能因 LLM 故障而中断全行经理的回顾生成 |
| **资讯源优先级** | Tushare → 新浪财经 → 东方财富(暂不可用) | — | Tushare 结构化数据最完善，新浪 API 稳定可靠 |
| **面谈转写 LLM 温度** | 0.2（低） | 0.5 | PDCA 提取和画像变更需要高稳定性，不宜过度创造 |
| **周报生成频率** | 每周一 08:00 | 每周日 20:00 | 与 ReportAgent（经营周报）错开，周一上午是最佳回顾时机 |

## 七、与现有 Agent 的协作

```
                    ┌──────────────────┐
                    │   data_engine     │  每日 07:30 数据注入
                    │   (日增引擎)      │
                    └────────┬─────────┘
                             │ product_updates, announcements
                             ▼
                    ┌──────────────────┐
                    │   news_fetcher    │  每日 08:30 资讯抓取
                    │   (资讯抓取)      │
                    └────────┬─────────┘
                             │ daily_news
                             ▼
              ┌──────────────────────────────┐
              │       ContentAgent            │
              │   (内容生成智能体)             │
              │                              │
              │  gen_digest  ← 08:35 资讯摘要 │
              │  gen_review  ← 20:00 昨日回顾 │
              │  gen_summary ← 周一 08:00 周报│
              │  transcribe_dictation 面谈转写│
              └──────────────────────────────┘
                             │
            ┌────────────────┼────────────────┐
            ▼                ▼                 ▼
    ┌──────────────┐  ┌───────────┐  ┌────────────────┐
    │ SchedulerAgent│  │  QAAgent  │  │  下游消费者     │
    │ 排程后回顾    │  │ 问答互补  │  │  前端展示       │
    └──────────────┘  └───────────┘  └────────────────┘
```

- **与 SchedulerAgent**：SchedulerAgent 做排程（forward-looking），ContentAgent 做回顾（backward-looking），形成「计划→执行→回顾」闭环
- **与 QAAgent**：QAAgent 回答客户经理提问（按需交互），ContentAgent 主动推送信息摘要（定时推送），互补不重叠
- **与 CustomerInsightAgent**：InsightAgent 做客户级别深度分析，ContentAgent 做经理级别信息汇总，不同粒度

# QAAgent · 智能问答助手设计方案

> **版本**：v1.0 | **日期**：2026-07-30 | **状态**：✅ 已实现
>
> **定位**：基于 RAG（ChromaDB + DashScope text-embedding-v3）增强的银行零售业务智能问答专家，为客户经理提供产品信息查询、业务知识解答和综合理财建议。

---

## 一、业务诉求

### 1.1 核心痛点

客户经理在日常工作中面临大量的产品和业务知识问答需求：

- **知识分散**：产品信息、办理流程、政策法规分散在多个系统和文档中，查找效率低
- **规则复杂**：银行业务受严格监管，回答客户问题必须遵循合规约束，不可随口承诺
- **更新频繁**：产品迭代、政策调整频繁，客户经理难以实时掌握最新信息
- **风险高**：不当回答可能引发合规风险（如承诺保本保收益、简化办理门槛等）

### 1.2 核心价值

| 能力 | 传统做法 | QAAgent RAG 增强 |
|------|---------|-----------------|
| **产品查询** | 翻阅产品手册/系统 | 自然语言提问，语义检索精准匹配 |
| **业务解答** | 凭经验或咨询同事 | 检索 1450 条知识文档 + 383 条合规规则，有据可依 |
| **合规拦截** | 依赖个人合规意识 | 自动匹配规则约束，违规请求按标准话术拦截 |
| **配置建议** | 手工筛选匹配 | 结合客户画像 + 知识库多因子推荐 |
| **规则溯源** | 难以追溯依据 | 每条回答标注规则编号出处 |

### 1.3 业务场景

| 场景 | 触发方 | 频率 | 说明 |
|------|:---:|------|------|
| **产品查询** | 客户经理 | 按需 | "有什么R2理财"、"推荐几款活期产品" |
| **产品解读** | 客户经理 | 按需 | "结构性存款是什么"、"大额存单和定期区别" |
| **业务问答** | 客户经理 | 按需 | "个人住房贷款需要什么材料"、"怎么申请信用卡" |
| **配置建议** | 客户经理 | 按需 | "客户50万闲置半年怎么配置" |
| **合规咨询** | 客户经理 | 按需 | "能不能免面签"、"可以承诺保本吗" |

## 二、流程设计

### 2.1 核心流程（RAG 增强问答）

```
客户经理提问
  │
  ├─→ QAAgent.ask(ctx, {question, manager_id, history})
  │     │
  │     ├─→ Step 1: 确保 RAG 索引就绪
  │     │     ensure_index() → build_index(force_rebuild=False)
  │     │     首次启动自动构建，后续复用已有索引
  │     │
  │     ├─→ Step 2: 意图分类
  │     │     _classify_intent(question)
  │     │     ├── product_search    ("有什么"、"推荐")
  │     │     ├── product_explain   ("是什么"、"区别")
  │     │     ├── business_qa       ("怎么"、"流程"、"条件")
  │     │     ├── allocation_advice ("配置"、"买什么" + 金额)
  │     │     └── general           (其他)
  │     │
  │     ├─→ Step 3: RAG 检索
  │     │     retriever.retrieve_for_qa(query)
  │     │     ├── 查询向量化（DashScope text-embedding-v3，1024维）
  │     │     ├── 知识检索（rag_knowledge，top_k=6，阈值 1.8）
  │     │     ├── 规则检索（rag_business_rules，top_k=12，阈值 1.2）
  │     │     └── 违规识别（风险警示/禁止类规则标记）
  │     │
  │     ├─→ Step 4: 构建 Prompt + 调用 LLM
  │     │     _generate_answer(question, intent, retrieval, history)
  │     │     ├── System Prompt: prompts/qa_assistant.md
  │     │     ├── User Prompt: 意图提示 + 知识上下文 + 规则上下文 + 用户问题
  │     │     ├── Model: DeepSeek V4 Flash, temperature=0.3
  │     │     └── 降级: LLM 不可用时直接返回检索结果
  │     │
  │     └─→ Step 5: 组装返回结果
  │           return {answer, intent, sources, matched_rules, ...}
  │
  └─→ 前端渲染回答（Markdown 格式）
```

### 2.2 RAG 检索增强流程

```
用户问题: "个人住房贷款怎么申请？"
  │
  ├─→ Embedder.embed_query(question)
  │     enhanced_query = "为下述问题检索相关知识：个人住房贷款怎么申请？"
  │     → DashScope API → [1024维向量]
  │
  ├─→ VectorStore.search_knowledge(query_embedding, top_k=6)
  │     ┌─────────────────────────────────────────────┐
  │     │ rag_knowledge (1450 chunks)                  │
  │     │ ├─ 产品介绍 (R2产品/存款/理财/贷款/银行卡)     │
  │     │ ├─ 业务流程 (申请/审批/签约/放款)              │
  │     │ ├─ 政策法规 (国家法律/监管规章/行业规范)        │
  │     │ ├─ 渠道服务 (手机银行/网银/柜面/远程)          │
  │     │ ├─ 业务对象 (个人客户/账户/风控)              │
  │     │ └─ 零售业务基础 (分类/定义)                   │
  │     └─────────────────────────────────────────────┘
  │
  ├─→ VectorStore.search_rules(query_embedding, top_k=12)
  │     ┌─────────────────────────────────────────────┐
  │     │ rag_business_rules (383条规则)                │
  │     │ ├─ 个人贷款管理办法 (59条)                     │
  │     │ ├─ 理财业务监督管理办法                         │
  │     │ ├─ 信用卡业务监督管理办法                       │
  │     │ ├─ 互联网贷款管理暂行办法                       │
  │     │ ├─ 消费者权益保护管理办法                       │
  │     │ ├─ 个人金融信息保护规定                         │
  │     │ └─ 金融资产风险分类办法                         │
  │     └─────────────────────────────────────────────┘
  │
  └─→ format_context(retrieval) → LLM 上下文
        ├─ 知识文档: 标题、来源、内容片段
        ├─ 业务规则: 规则编号、场景类型、标准话术
        └─ 违规警示: 需重点审查的禁止类规则
```

### 2.3 关键设计决策

| 决策点 | 选择 | 理由 |
|-------|------|------|
| **向量库** | ChromaDB 嵌入式（本地持久化） | 无需独立服务，与 SQLite 类似的零运维成本 |
| **Embedding 模型** | 百炼 DashScope text-embedding-v3（1024维） | OpenAI 兼容协议，中文语义理解优秀 |
| **文档分块** | 按 `##` 标题切分，≤1500 字符，200 字符重叠 | 保留章节语义完整性，避免截断关键信息 |
| **规则独立性** | 规则文档独立 Collection（rag_business_rules） | 规则匹配阈值更严格，便于合规审查和溯源 |
| **规则 ID 策略** | `源文件名:R编号` 格式 | 7 个规则文件共存，避免 R00001 跨文件冲突 |
| **批量大小** | 10 条/批次 | DashScope text-embedding-v3 API 硬限制 |
| **意图分类** | 规则匹配优先（无需 LLM） | 轻量、低延迟、零成本 |
| **降级策略** | LLM 不可用时返回检索原文 | 保证系统可用性，不阻断核心流程 |
| **问答模型** | DeepSeek V4 Flash | 与平台其他智能体统一，速度快成本低 |
| **输出格式** | 遵循 AI对话约束规则.md 模板 | 合规判断 → 规则依据 → 业务解答 |

### 3.3 数据模型

#### 知识文档 Chunk 元数据

| 字段 | 类型 | 说明 |
|------|------|------|
| source | TEXT | 源文件相对路径（如 `02-零售业务产品介绍/贷款产品/01-个人住房贷款.md`）|
| title | TEXT | 文档标题（一级 `#` 标题）|
| section | TEXT | 当前小节标题（`##` 标题）|
| category | TEXT | 业务类别（产品介绍/业务流程/政策法规/渠道服务/业务对象/零售业务基础）|
| sub_category | TEXT | 子类别（如"贷款产品"）|
| chunk_index | TEXT | 分块序号 |

#### 业务规则元数据

| 字段 | 类型 | 说明 |
|------|------|------|
| rule_id | TEXT | 唯一规则 ID（`源文件名:R编号`，如 `01-个人贷款管理办法-AI业务规则约束:R00001`）|
| scenario | TEXT | 适用场景描述（含 `[信息咨询]`/`[业务咨询]`/`[风险警示]` 等标签）|
| scenario_type | TEXT | 场景类型（信息咨询/业务咨询/风险警示/合规警示）|
| tags | TEXT | 规则标签 |
| source | TEXT | 源规则文件相对路径 |

#### 检索结果 (RetrievalResult)

| 字段 | 类型 | 说明 |
|------|------|------|
| query | TEXT | 原始查询文本 |
| knowledge_chunks | list[dict] | 匹配的知识文档片段（含 id/document/metadata/distance）|
| matched_rules | list[dict] | 匹配的业务规则（含 id/document/metadata/distance）|
| rule_violations | list[dict] | 可能违规的规则（场景类型为风险警示/合规警示，或标签含"禁止"/"违规"）|

### 3.4 Prompt 设计

**System Prompt**（`prompts/qa_assistant.md`, 52 行）：

```
一、角色定义
  - 银行零售业务专家级顾问（QAAgent）
  - 回答基于 RAG 检索到的知识文档和业务规则约束
  - 所有输出严格遵循已检索到的规则文档

二、核心原则
  1. 规则优先：违规先拦截，标注规则编号
  2. 知识驱动：引用检索片段，不编造事实
  3. 风险提示：产品推荐标注风险等级/适用人群/限制
  4. 禁止行为：不承诺保本保收益、不简化监管门槛、
     不突破贷款用途限制、不保证获批

三、输出格式要求
  - 有规则匹配时：合规判断 → 规则依据 → 业务解答
  - 无规则冲突时：直接业务解答
  - 检索不足时：诚实说明信息有限

四、产品推荐规范
  - 表格罗列：产品名称|类型|风险等级|期限|起购金额|业绩基准|适用场景
  - 必须附带风险提示
  - 涉及利率/费率标注数据参考时点
```

**User Prompt 构建逻辑**（`_build_user_prompt`）：

```
# 用户意图
{intent_hints[意图类型]}

# 知识上下文
## 相关知识文档
### 1. **文档标题** _(来源: 文件路径)_
{检索到的知识文档内容}

## 匹配的业务规则约束
### 规则 1. **R编号** [场景类型]
{规则内容 - 规则编号、场景、话术、标签}

# 用户当前提问
{原始问题}

# 输出要求
1. 先判断用户请求是否违反上方任意约束规则
2. 违规：直接按规则标准话术拦截，标注违规规则ID
3. 合规：基于知识文档给出业务解答，关键办理条件引用原文
4. 禁止出现规则未提及的承诺、简化门槛、放宽限制
```

### 3.5 向量检索参数

| 参数 | 知识检索 | 规则检索 | 说明 |
|------|:---:|:---:|------|
| top_k | 6 | 12 | 规则检索更多以防遗漏 |
| distance_threshold | 1.8 | 1.2 | 规则匹配更严格（余弦距离越小越相关）|
| 检索方法 | `retrieve_for_qa()` | 同 | 统一检索入口 |

## 四、调用设计

### 4.1 API 端点（规划）

| 端点 | 方法 | 说明 | 响应方式 |

### 4.4 Agent 间协作

```
                          ┌──────────────────┐
                          │   RouterAgent     │
                          │  (对话路由/意图分发) │
                          └────────┬─────────┘
                                   │
                    ┌──────────────┼──────────────┐
                    │              │              │
                    ▼              ▼              ▼
           ┌─────────────┐ ┌───────────┐ ┌─────────────┐
           │  QAAgent    │ │ BattlePkg │ │ ContentAgent │
           │ (业务问答)    │ │ (作战包)   │ │ (内容生成)    │
           └──────┬──────┘ └───────────┘ └─────────────┘
                  │
    ┌─────────────┼─────────────┐
    │             │             │
    ▼             ▼             ▼
┌────────┐  ┌──────────┐  ┌──────────┐
│ RAG 知识库│  │ 产品数据库 │  │ AI对话约束 │
│(ChromaDB)│  │ (JSON)    │  │ 规则      │
└────────┘  └──────────┘  └──────────┘

协作关系：
- RouterAgent → QAAgent: 意图识别为产品/业务问题时路由至此
- QAAgent → BattlePkgAgent: 产品推荐结果可作为作战包输入（规划中）
- QAAgent → ContentAgent: 问答历史可作为面谈总结素材（规划中）
```

### 6.2 规则结构

每条规则包含：
- **规则编号**：R00001-R00059（每个文件独立编号）
- **适用场景**：`[信息咨询]` / `[业务咨询]` / `[风险警示]` / `[合规警示]`
- **规则话术**：标准回复话术
- **规则标签**：分类标签

### 6.3 违规拦截示例

| 用户问题 | 匹配规则 | 合规判断 | 响应 |
|---------|---------|:---:|------|
| "能不能不面签就办贷款" | R00017/R00018 | ⚠️ 部分违规 | 线上小额贷款可豁免面签，≥20万或≥1年仍需线下 |
| "能保证这个理财不亏吗" | 理财监督类规则 | ❌ 违规 | 按"不得承诺保本保收益"标准话术拦截 |
| "帮忙免掉风险评估行不行" | 消费者权益类规则 | ❌ 违规 | 按"不得简化监管要求的办理门槛"拦截 |
| "有没有收益5%以上的保本产品" | 理财监督类规则 | ❌ 违规 | 提示保本产品收益上限，建议调整预期 |

## 八、技术选型总表

### 8.1 后端 / AI 引擎

| 层级 | 组件 | 选型 | 说明 |
|------|------|------|------|
| **API 框架** | 后端 | FastAPI | 原生 async，SSE 流式支持好，已有项目基础 |
| **Agent 框架** | Agent Harness | 自研轻量 | 声明式 `@agent`，场景明确无需 LangChain 复杂度 |
| **模型适配** | 统一接口 | LiteLLM | 支持 OpenAI/Claude/Qwen/Ollama 等 100+ 模型 |
| **流式输出** | 协议 | SSE | 比 WebSocket 轻量，浏览器原生 `EventSource` |
| **技能执行** | Skill Executor | 自研沙箱 | 白名单注册 + 参数校验 + 限流 + 审计 |
| **上下文记忆** | 存储 | Redis / dict | 按 user_id+agent 维度隔离，TTL 自动过期 |
| **定时调度** | 调度器 | APScheduler + Celery | APScheduler 定义 cron，Celery 分布式执行 |
| **工作流编排** | 编排引擎 | Celery Canvas | chain/group/chord 原生 DAG 支持 |
| **消息队列** | Agent间通信 | Redis Pub/Sub | 轻量，已有 Redis 则零额外依赖 |
| **提示词管理** | 模板 | Markdown + Jinja2 | 可版本控制，非开发人员可调优 |
| **向量检索** | 知识库 | ChromaDB | RAG 场景：产品知识/合规条款/话术库检索 |
| **语音输入** | 语音 | Web Speech API → Whisper | 浏览器端采集 + 后端转写 |
| **可观测性** | 监控 | Prometheus + 自研 Dashboard | Token消耗/Agent调用/任务队列深度 |

### 8.2 前端技术栈

| 层级 | 组件 | 选型 | 版本 | 说明 |
|------|------|------|------|------|
| **框架** | Vue 3 | Composition API | ^3.4 | `<script setup>` + TypeScript，响应式系统 |
| **构建工具** | Vite | — | ^5.4 | 极速 HMR，ESBuild 预构建 |
| **UI 组件库** | Vant 4 | — | ^4.9 | 移动端优先，按需自动导入 |
| **路由** | Vue Router 4 | History 模式 | ^4.3 | 懒加载路由，22 个视图页面 |
| **状态管理** | Pinia | Composition Store | ^2.1 | 5 个 Store 模块，API 回落静态数据 |
| **语言** | TypeScript | Strict 模式 | ~5.4 | 接口定义 + 枚举常量 |
| **CSS 方案** | Scoped CSS | CSS 自定义属性 | — | 内联 `<style scoped>`，`--color-*` Token |
| **按需导入** | unplugin-vue-components | VantResolver | ^0.27 | Vant 组件零手动 import |
| **路径别名** | `@/` → `src/` | — | — | Vite `resolve.alias` + tsconfig `paths` 双重配置 |
| **图标方案** | Emoji 字符 | — | — | 零依赖跨平台一致渲染 |

### 8.3 设计决策：为什么选 Vue 3 而非 React

| 维度 | Vue 3 | React | 选择理由 |
|------|-------|-------|----------|
| **原型来源** | `workbench.html` 是单文件 HTML+JS，迁移到 `.vue` SFC 最自然 | JSX 需大量改写 HTML 模板 | Vue 模板语法与原 HTML 结构 1:1 对应，迁移成本最低 |
| **移动端组件** | Vant 4 是 Vue 生态的顶级移动端 UI 库 | 无同等成熟的 React 移动端库（Ant Design Mobile 功能偏少） | Vant 提供 NavBar/TabBar/Popup/Toast 等开箱即用的移动端组件 |
| **学习曲线** | 渐进式，`.vue` 单文件组件直观 | JSX + Hooks 心智负担较高 | 团队快速上手，非前端开发者也能读懂模板 |
| **状态管理** | Pinia 与 Vue 3 Composition API 原生集成 | Zustand/Redux 需额外选择 | Pinia 是 Vue 官方推荐，API 极简 |
| **构建体积** | Vite + Tree Shaking 后约 210KB CSS + 43 个 JS chunk | 类似 | 两者相当 |

## 十一、关键设计决策

### 11.1 后端 / AI 引擎

| 决策点 | 选择 | 理由 |
|-------|------|------|
| **Agent 框架** | 自研轻量，不依赖 LangChain | 场景明确、Agent 数量可控，自研框架更易维护和调试 |
| **多 Agent 协作** | RouterAgent 意图分发 + Celery Canvas 工作流 | 对话场景由 Router 分发；批量任务由 Canvas 编排，职责清晰 |
| **模型网关** | LiteLLM | 社区活跃、模型覆盖全、API 兼容 OpenAI SDK |
| **定时调度** | APScheduler(开发) → Celery(生产) | 渐进式升级，开发阶段无需 Redis |
| **流式协议** | SSE 而非 WebSocket | 单向流足够，浏览器原生支持，实现简单 |
| **技能管理** | 白名单注册 + 装饰器声明 | 安全可控，避免 Agent 任意调用函数 |
| **提示词管理** | Markdown 文件 + 版本控制 | 可 diff/可 review/非开发人员可编辑 |
| **Agent 粒度** | 13 个，按领域划分 | 内聚性好，每个 Agent 职责单一，prompt 可精细调优 |
| **模型粒度** | 按 Agent 独立指定 | 高价值任务(商机挖掘/作战包)用强模型，摘要类用轻量模型，控制成本 |
| **不引入向量库** | MVP 阶段用全文检索 + prompt 注入 | 数据量小，向量库 ROI 待验证 |

### 11.2 前端工程化

| 决策点 | 选择 | 理由 |
|-------|------|------|
| **框架** | Vue 3 Composition API | 与原型 HTML 模板结构 1:1 对应，迁移成本最低 |
| **组件库** | Vant 4 | 移动端 UI 最成熟，NavBar/TabBar/Popup 开箱即用 |

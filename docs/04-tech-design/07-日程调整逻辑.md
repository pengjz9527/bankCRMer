# 日程调整设计逻辑

> 对应原型：W2 日程处理与调整 — 模块 2.2
> 版本：v1.0 | 日期：2026-07-17

---

## 一、功能定位

日程调整让客户经理可以**手动修正** AI 自动排程的结果。调整**仅当日有效**，次日 AI 会根据最新待办池重新生成全新排程。

核心原则：
- AI 排程是**基准**，手动调整是**临时覆盖**
- 不让"昨天的临时调整锁死明天的日程"
- 所有调整即时反馈，AI 自动重算避免时间冲突


## 四、三大调整操作

### 4.1 调整时段（拖拽排序）

| 操作 | 行为 | 说明 |
|------|------|------|
| 长按 ⠿ 手柄 | 卡片浮起，阴影加深 | （原型中用手柄表示可拖拽，实际拖拽待手势库支持） |
| 向上拖 | 序号减小，往前排 | 上方卡片自动下移 |
| 向下拖 | 序号增大，往后排 | 下方卡片自动上移 |
| 跨越上午/下午 | ☀️ ↔ 🌤 自动切换 | 时段标签联动 |
| 松手 | 落位 + AI 重算时间 | 所有受影响卡片时间闪烁更新 |

**当前原型替代方案**：拖拽手柄为视觉标记（⠿），实际排序通过"上移/下移"按钮操作（后续上线前补齐 iOS 手势）。

### 4.2 修改时间

| 操作 | 当前原型 | 正式方案 |
|------|----------|----------|
| 点击时间标签 | 循环切换 8 个预设时段 | iOS 风格时间滚轮 |
| 修改开始时间 | 预设值轮换 | 滚轮选择，结束时间自动计算 |
| 修改预计耗时 | 暂不支持 | 下拉选 15min/30min/1h/1.5h/2h |
| 时间冲突检测 | 暂未实现 | Toast 提示冲突 + AI 自动后移 |

**当前原型时间预设**：
```
08:00-09:30 / 09:00-10:30 / 10:00-11:30 / 11:00-12:00
13:00-14:00 / 14:00-15:00 / 15:00-16:00 / 16:00-17:00
```
每次点击切换到下一个预设值，循环轮转。

### 4.3 跳过 / 推迟

#### 普通待办卡片

| 按钮 | 行为 | 持久化 |
|------|------|--------|
| **推迟今天晚些** | 移到最后一张，重新分配时段 | 当日有效 |
| **推迟到明天** | 从今日清单移除，加入明日待办 | 跨日保留 |
| **今天不处理** | 从今日清单移除，回到待办池 | 保留待办池 |

#### 商机待办卡片

| 按钮 | 行为 |
|------|------|
| **推迟拜访** | 移到最后 + Toast |
| **取消拜访** | 从清单移除 + Toast |

**动效**：点击后卡片 350ms 缩小淡出（scale 0.95 → opacity 0）。

## 五、AI 重新排程反馈

**触发时机**：任何手动调整（拖拽/改时间/跳过）后即时触发。

**反馈形式**：
- Block 2 底部出现**蓝色提示条**
- 文案："AI 已根据调整重新排程，预计总耗时 3.2 小时"
- **3 秒后自动消失**
- 每次新调整**刷新计时器**（不会在调整中途消失）

**AI 排程优先级**（时间冲突时按此顺序后移低优先级任务）：

```
产品到期 > 大额异动 > 贷款逾期 > 商机待办 > 生日提醒 > 联络超期 > 信用卡待办
```

## 六、退出调整模式

| 操作 | 行为 | 是否保存 |
|------|------|----------|
| **[完成调整]** | 退出调整模式，所有修改生效 | ✅ 保存（当日有效） |
| **[取消]** | 退出调整模式 | ❌ 撤销所有修改，恢复原排程 |

退出后：
- 虚线边框消失
- 拖拽手柄隐藏
- 时间标签恢复不可编辑
- 跳过按钮消失
- AI 反馈条移除
- 标题行恢复为 `[全部待办 >] [调整日程]`

## 七、持久化规则

```
每日 AI 排程 = 全新基准
        │
        ├── 手动调整（当日有效）
        │   ├── 卡片排序      → 次日重置
        │   ├── 时间修改      → 次日重置
        │   └── 推迟到晚些     → 次日重置
        │
        ├── 跨日操作
        │   └── 推迟到明天     → 加入明日待办清单
        │
        └── 永久操作
            ├── 今天不处理     → 回到待办池（次日可能重新排入）
            └── 处理完成       → 永久标记，不再出现
```

**关键设计理念**：

> "明天的日程不会被昨天的临时调整锁死。"
>
> 每天早晨 AI 扫描最新待办池，生成全新排程。客户经理昨天说"这个放到明天"的卡片会出现，但时间段由 AI 重新计算。昨天手动调到 15:00 的任务，今天可能排在 09:00——因为今天的待办组合不同了。

---

## 八、与普通处理的区别

| | 处理完成 | 跳过/推迟 |
|------|----------|-----------|
| 操作入口 | 点击卡片 → 处理面板 | 编辑模式 → 跳过按钮 |
| 对卡片影响 | 标记 √ 已完成 | 从今日排程移除 |
| 对客户影响 | 逐客户标记处理状态 | 客户状态不变 |
| 持久化 | 永久 | 取决于跳过类型 |
| 轮播行为 | 卡片消隐 → 自动前进 | 卡片淡出 → 轮播保持 |

## 十、设计决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 调整仅当日有效 | ✅ | 避免昨日临时调整锁死明日 |
| AI 重算反馈 3 秒消失 | ✅ | 提示不阻塞操作，非模态 |
| [取消] 撤销所有修改 | ✅ | 原子操作，要么全保存要么全撤销 |
| 商机待办独立跳过按钮 | ✅ | 商机操作语义不同（推迟拜访 vs 推迟任务） |
| 原型用点击切换时间替代滚轮 | ✅ | 原型阶段快速验证交互流程 |

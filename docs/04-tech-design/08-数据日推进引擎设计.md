# 数据日推进引擎设计

> **版本**：v1.0 | **日期**：2026-07-28 | **状态**：已实现
>
> 实现文件：`data-sim/data_engine.py`（约 460 行），调度集成：`data-sim/app.py`

---

## 一、背景与目标

### 1.1 问题

初始数据生成（`generate_data.py` / `app.py:gen_all()`）是一次性快照——180 天交易流水、90 天行为日志在首日全部生成完毕。此后不再有新数据注入，导致：

- `CustomerInsightAgent` 每周生成的 `change_signals` 完全相同
- `OppMiningAgent` 每次挖掘结果高度雷同
- `SchedulerAgent` 检测不到"昨日大额异动"
- 工作台待办卡片始终是同一批产品到期/大额异动

### 1.2 目标

构建**日增数据引擎**，每日自动注入新交易、行为、沟通数据，模拟真实银行客户的日常金融活动，使 AI Agent 体系能持续感知数据变化。

### 1.3 设计原则

| 原则 | 说明 |
|:---|:---|
| **增量追加** | INSERT ONLY，不修改历史数据，AI 产出数据（opportunities/insights/schedules）不受影响 |
| **幂等** | 同一天执行多次不会重复插入（`data_ticks` 表标记） |
| **画像驱动** | 基于客户静态属性（tier/AUM/occupation/age/emp_status）差异化行为模式 |
| **时间窗轮转** | Agent 查询的 180 天窗口自然滚动，旧数据退出 |
| **信号注入** | 低概率触发大额异动、他行转账、职业变动等关键事件 |

## 三、画像推导 (`derive_profile`)

不依赖原始模板（`templates.py` 中的 `ALL_TEMPLATES`），纯基于 `customers` 表的已存储字段推断日活参数。

### 3.1 日活概率

```
等级 → 日活概率映射:
  千元以下: 0.25    千元户: 0.22    万元户: 0.18
  优质:     0.15    财富:   0.12    高净值: 0.10
  私钻:     0.08    私行:   0.06

就业状态调整:
  无业/待业: ×0.4     自由职业: ×0.8
```

高 AUM 客户日活概率**更低**（对应模板中 `active_prob` 的分布规律），因为他们交易频率低但单笔金额大。

### 3.2 月交易频率

```
AUM > 500万 → 2笔/月
AUM > 100万 → 3笔/月
AUM > 20万  → 5笔/月
AUM > 5万   → 8笔/月
否则         → 12笔/月
```

每日交易笔数通过泊松采样（`λ = 月频率/30`）生成，周末减半。

### 3.3 行为偏好推导

从职业字段推断页面浏览偏好分布：

| 职业群 | 理财 | 基金 | 存款 | 保险 | 贷款 | 信用卡 |
|:---|:---:|:---:|:---:|:---:|:---:|:---:|
| 金融/管理（销售经理、企业中层、银行职员） | 35% | 25% | 20% | 10% | 5% | 5% |
| 技术（工程师、IT项目经理） | 20% | 35% | 15% | 5% | 15% | 10% |
| 稳定（教师、公务员、会计） | 25% | 15% | 35% | 15% | 5% | 5% |
| 医疗（医生、护士） | 25% | 20% | 20% | 20% | 10% | 5% |
| 自由职业 | 30% | 25% | 15% | 10% | 10% | 10% |
| 无业/待业 | 20% | 10% | 40% | 5% | 20% | 5% |

年龄修正：≥50 岁 +10%存款/+5%保险/-5%基金；≤30 岁 +5%基金/+5%信用卡。
等级修正：私钻/私行/高净值 +5%保险/+5%理财。

### 3.4 薪资判定

`employment_status='在职'` 且 occupation 属于典型上班族（工程师/教师/公务员/销售经理/会计/IT项目经理/医生/护士/企业中层/银行职员）→ 判定为代发薪客户，随机分配每月发薪日（8-12 日）。

### 3.5 周末感知

通过 `date.today().weekday() >= 5` 判定周六/日，影响：
- 交易频率减半
- 行为浏览时长翻倍（15-300s → 30-600s）
- 渠道偏好偏向手机银行/微信
- 活跃时段延后（8-22h → 9-23h）

## 四、生成器设计

### 4.1 交易生成 (`gen_transactions`)

**步骤 1 — 日常交易**

泊松采样确定今日交易笔数（上限 5 笔）。每笔：
- 方向：50% 收入 / 50% 支出
- 金额：收入 ≤ AUM×0.8%，支出 ≤ AUM×1%
- 对手方：支付宝/微信/他行账户/本行账户/商户/个人/公司
- 摘要：工资/转账/消费/理财购买/取现/红包 等
- 渠道：手机银行（偏重）/网银/柜台/ATM

**步骤 2 — 信号注入**

| 信号 | 概率 | 条件 | 金额范围 |
|:---|:---:|:---|:---|
| 发薪 | 70%（发薪日当天） | `is_salary_worker ∧ today.day == salary_day` | 1500-200000（按等级分档） |
| 大额异动 | 5%/日 | 无条件 | AUM×3%~20%，封顶 500000 |
| 经营流水 | 25%/日 | `occ='企业中层'` | 5000-80000 |
| 他行转账 | 2%/日 | 无条件 | AUM×3%~15%，最低 10000 |

### 4.2 行为生成 (`gen_behaviors`)

**触发判断**：`random() < behavior_daily_prob`（约 5%-12%，与日活概率正相关）。

**条数**：1-3 条（周末偏 2-3 条），按权重 `[0.6, 0.3, 0.1]` 采样。

**详情**：
- 页面：按 `behavior_bias` 加权随机
- 动作：浏览/搜索/点击详情/收藏/对比
- 时长：工作日 15-300s，周末 30-600s
- 时段：工作日 8-22h，周末 9-23h
- 渠道：工作日手机银行为主，周末加入微信

### 4.3 持仓到期处理 (`process_maturing_holdings`)

1. `UPDATE holdings SET status='已到期' WHERE maturity_date=today`
2. 20% 概率自动续购同类新产品（金额为原持有额 ×0.8~1.2，期限 30/60/90/180/365 天随机）

### 4.4 客户经理沟通 (`gen_manager_communications`)

**大额异动回访**：查询昨日 >30000 的出金交易，40% 概率电话/微信回访。

**产品到期提醒**：查询 7 日内到期产品的前 3 位客户，50% 概率发微信提醒。

### 4.5 稀缺事件 (`inject_rare_events`)

| 事件 | 日概率 | 操作 |
|:---|:---:|:---|
| 职业变动 | 0.3% | 随机选 1 位客户，变更 `employment_status`（在职↔待业↔自由职业），同步更新 `employment_status` 表 |

## 五、幂等机制

```sql
CREATE TABLE data_ticks (
    tick_date TEXT PRIMARY KEY,   -- 推进日期 YYYY-MM-DD
    stats_json TEXT NOT NULL,     -- 当日生成统计 {"transactions": N, ...}
    created_at TEXT NOT NULL      -- 记录时间
);
```

执行流程：
1. `SELECT tick_date FROM data_ticks WHERE tick_date = ?`
2. 若已存在 → 返回 `{"status": "skipped"}`
3. 若不存在 → 执行生成 → `INSERT INTO data_ticks`

## 六、调度集成

### 6.1 注册位置

`app.py` 的 `start_scheduler()` 中：

```python
scheduler.add_job(scheduled_data_tick, "cron", hour=7, minute=30, id="daily_data_tick")
scheduler.add_job(scheduled_schedule_gen, "cron", hour=8, minute=0, id="daily_schedule_gen")
scheduler.add_job(scheduled_insight_generation, "cron", day_of_week="sun", hour=3, minute=0, id="weekly_insight_gen")
```

### 6.2 时间线

```
07:30  data_tick     — 注入当日增量数据
08:00  schedule_gen  — 基于新鲜数据（含"昨日"异动）生成待办和日程
       (此时 query_tasks_for_schedule 可检测到昨日新增的大额异动)

周日:
03:00  insight_gen   — 经过 7 天日增，change_signals 每周都有新变化
```

### 6.3 手动触发

```bash
cd data-sim
python3 -c "from data_engine import daily_tick; from datetime import date; print(daily_tick(date.today().isoformat()))"
```

## 七、数据影响范围

| 表 | 操作 | 日增量 | 说明 |
|:---|:---|:---:|:---|
| `transactions` | INSERT | 2-40 笔 | 日常消费 + 信号注入 |
| `behavior_logs` | INSERT | 0-30 条 | 画像驱动浏览 |
| `communications` | INSERT | 0-5 条 | 经理响应式沟通 |
| `holdings` | UPDATE + INSERT | 0-3 笔 | 到期标记 + 自动续购 |
| `employment_status` | UPDATE + UPSERT | 0-1 条 | 极低概率职业变动 |
| `customers` | UPDATE | 0-1 行 | 仅 employment_status 字段 |
| `data_ticks` | INSERT | 1 行 | 幂等标记 |

**不影响的表**：`family_info`、`business_info`、`loans`、`loan_rejections`、`risk_assessments`、`product_catalog`、`customer_benefits`、`available_activities`、`customer_relations`、`cust_manager_rel`、`opportunities`、`customer_insights`、`daily_schedules`、`battle_packages`、`battle_package_clues`、`kpi_*`、`processing_records`。

## 八、扩展点

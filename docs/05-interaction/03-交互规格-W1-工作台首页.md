# 交互规格 — W1 工作台首页

> **定位**：客户经理每日打开 APP 的默认着陆页。聚合展示待办、日程、商机、新客四大核心信息，是所有操作的入口和中枢。
>
> **设计约束**：本文档中待办、商机、作战包的交互链路以《核心业务设计模型-待办商机作战包.md》为权威依据。
>
> **版本**：v1.0 | **最后更新**：2026-07-15

---

### 1.2 滚动策略

- 页面整体可垂直滚动（`scroll-content`），Header 和 Tab Bar 固定
- 一屏约显示 Block 1 + Block 2(完整) + Block 3 目标区 + 页签标题行
- 向下滚动可看到 Block 3 页签内容 + Block 4
- Block 4 为条件显示：当客户基数充足且商机缺口不突出时可折叠或隐藏

### 1.3 数据来源总览

| Block | 数据来源 | 刷新频率 | 备注 |
|------|------|------|------|
| Block 1 AI 摘要 | AI 智能中枢 | T+1 每日推送 | 基于昨日数据 + 今日待办清单生成 |
| Block 2 日程 | 易知客待办系统 + AI 排程 | T+1 + 实时更新 | 处理完成后实时移除 |
| Block 3 商机看板 | 数仓/大数据平台/AI 挖掘 | T+1 + 按需刷新 | 商机挖掘为按需触发 |
| Block 4 新客拓展 | AI 智能中枢 | 按需生成 | 触发条件：商机缺口 + 管户基数不足 |

## 二、Block 1：AI 智能摘要条

### 2.1 视觉规范

- 样式：紫色左边框（3px `#6C5CE7`）+ 浅紫背景（`#F3F0FF`）+ AI 头像
- 无 section-header，无标题
- 高度自适应内容，不占用过多首屏空间

### 2.2 内容字段

| 字段 | 示例 | 说明 |
|------|------|------|
| 待办总数 | `8项` | 今日普通待办 + 商机待办的总数 |
| AI 建议主文本 | `AI已根据紧急程度和预计耗时完成智能排程` | 固定句式 |
| 上午策略 | `上午优先处理高价值到期客户` | AI 根据待办类型和客户价值动态生成 |
| 下午策略 | `下午集中联络超期客户` | 同上 |
| 预计总耗时 | `3.5小时` | AI 估算今日全部待办所需时间 |

### 2.3 交互行为

| 触发 | 行为 | 跳转目标 |
|------|------|------|
| 点击整个横幅 | 展开 AI 排程详细建议浮层 | 浮层（不跳页），展示每项待办的排程理由 |
| 浮层内 [调整排程] | 进入 Block 2 日程调整模式 | 滚动到 Block 2，激活调整态 |

### 2.4 AI 排程详细建议浮层

## 三、Block 2：今日日程安排

> **说明**：本 Block 的深度交互（卡片处理、日程调整、全部待办列表）在第二步详设。此处仅定义首页层面的展示规格和跳转契约。

### 3.1 视觉规范

- 容器：白色卡片 `schedule-block`，圆角 12px，自带阴影
- 标题栏：`section-header`，左侧"📋 今日日程安排"，右侧"5项待办 · 左右滑动切换"
- 轮播：单卡片居中，每次仅显示一张，底部数字页码指示器（1 2 3 4 5 6）
- 卡片宽度 100%，当前页码以品牌红圆形背景高亮显示

### 3.2 卡片字段定义

每张日程卡片包含以下字段：

| 字段 | 说明 | 示例 |
|------|------|------|
| 时段标签 | `☀️ 上午` 或 `🌤 下午`，橙底/蓝底 | ☀️ 上午 |
| 序号 | `#1` ~ `#N`，灰色小标签 | #1 |
| 类型标签 | 待办类型，带颜色编码 | 产品到期（红）/ 大额异动（橙）/ 生日提醒（绿）/ 联络超期（灰） |
| 商机标识 | 🟣 商机待办专用，携带 📋 作战包图标 | 🟣📋 |
| 任务摘要 | 2 行文字，含关键数字 bold | `3位客户产品到期，金额合计80万` |
| 建议时段 | AI 排程的时间窗口 | `09:00-10:30` |
| 预计耗时 | 该任务预计所需时间 | `约1.5h` |
| 涉及人数 | 该任务涉及的客户数量 | `3人` |
| 主操作按钮 | `[开始处理]` 或 `[查看名单]` | 根据待办类型区分 |

### 3.3 卡片类型颜色编码

| 待办类型 | 类型标签 class | 颜色 | 主操作按钮 |
|------|------|------|------|
| 产品到期 | `tag-danger` | 红色 | [开始处理] |
| 大额异动 | `tag-warning` | 橙色 | [开始处理] |
| 贷款逾期 | `tag-warning` | 橙色 | [开始处理] |
| 生日提醒 | `tag-success` | 绿色 | [开始处理] |
| 联络超期 | `tag-muted` | 灰色 | [查看名单]（无处理按钮） |
| 信用卡待办 | `tag-muted` | 灰色 | [开始处理] |
| 商机待办 | `tag-opportunity` | 🟣 紫色 | [查看作战包] |

### 3.4 轮播交互

日程卡片采用**水平轮播布局**，每次仅显示一张完整卡片。用户通过左右滑动或点击底部数字页码（1-6）切换卡片。每张卡片独立展开/折叠详情。

### 3.5 点击卡片的跳转契约（首页层面）

| 待办类型 | 点击行为 | 跳转目标 |
|------|------|------|
| 普通待办卡片 | 进入该待办的处理详情 | W2 待办处理详情（第二步设计） |
| 商机待办卡片 | 查看关联作战包 | P1 作战包首页（第四步设计） |
| [开始处理] 按钮 | 同上，进入处理详情 | W2 |
| [查看作战包] 按钮 | 查看关联作战包 | P1 |

### 3.6 标题栏入口

| 入口 | 行为 | 跳转目标 |
|------|------|------|
| [全部待办 >] | 进入按类型分组的待办列表 | W2 全部待办列表视图（第二步设计） |
| [调整日程] | 进入日程调整模式 | Block 2 内激活调整态（第二步设计） |

### 3.7 展开/折叠逻辑（当前原型已有）

- 点击卡片底部"展开详情 ▼"→ 展开该卡片关联的客户子列表
- 每个子项包含：客户姓名、关键信息、[处理] 按钮
- 再次点击或点击其他卡片时收起
- 多客户待办（产品到期/生日提醒/联络超期）默认展开，单客户待办默认收起

## 四、Block 3：商机看板

### 4.1 视觉规范

- 容器：白色卡片 `opp-board-card`，圆角 12px
- 标题栏：`section-header`，左侧"💡 商机看板"，右侧"详情 ›"
- 内部分为：目标进度区 + 双页签（当前商机 / 商机挖掘）

### 4.2 目标进度区

| 字段 | 说明 | 示例 |
|------|------|------|
| 核心指标 | AUM 净增大字 | `+128万` |
| 目标值 | 本月目标 | `200万` |
| 完成率 | 进度条 + 百分比 | `64%` |
| 剩余金额 | 距目标差额 | `72万` |
| 转化率 | 商机→AUM 转化比例 | `15%` |
| 所需商机 | 基于转化率倒算 | `12个商机` |
| 金额缺口警告 | 现有商机预估贡献不足时红色高亮 | `27万缺口` |

### 4.3 双页签

#### 页签一：「当前商机」

- 统计栏（三个 pool-stat）：当前商机数 / 预计贡献 / 金额缺口
- 商机列表：每行一条商机，含来源标识、客户数、预估价值、操作入口

| 列表项 | 来源 | 显示字段 |
|------|------|------|
| 代发即将到账 | 系统推送（来源一） | 客户数、月均代发金额、预估贡献 |
| 流失预警挽回 | 系统推送（来源一） | 客户数、流失概率、预估贡献 |
| AI 智能挖掘 | AI 挖掘（来源三） | 客户数、置信度、推理说明、预估贡献 |
| 我的商机 | 客户经理创建（来源二） | 客户数、创建时间、预估贡献 |

- 每行操作文字：`跟进 ›`（流失预警用 `紧急 ›` 红色）

#### 页签二：「商机挖掘」

- 显示条件：当前商机预估贡献 < 目标缺口所需金额
- 内容：
  - 缺口标签：`目标缺口 N个`
  - AI 挖掘方向列表（沉睡客户激活、代发新名单、交叉销售等）
  - 合计可挖掘预估
  - [一键 AI 挖掘] 按钮

### 4.4 交互行为

| 触发 | 行为 | 跳转目标 |
|------|------|------|
| 点击 [详情 ›] | 进入完整商机分析 | W3 商机管理页（第三步设计） |
| 点击页签「当前商机」 | 切换到当前商机面板 | Block 3 内切换 |
| 点击页签「商机挖掘」 | 切换到商机挖掘面板 | Block 3 内切换 |
| 点击商机列表行 | 查看该商机详情 | W3 商机详情 |
| 点击 [跟进 ›] | 进入商机跟进流程 | W3 → [生成作战包] → P1 |
| 点击 [一键 AI 挖掘] | 触发 AI 商机挖掘 | 后台启动挖掘 → 结果推送至 W3 |
| 商机挖掘完成 | 当前商机数刷新 | 首页 Block 3 数据更新 |

### 4.5 商机看板与核心业务模型的对齐

- 商机列表需覆盖三来源：系统推送 + AI 挖掘 + 客户经理创建
- 商机 ≠ 待办：商机看板不直接生成待办，需通过"生成作战包"链路
- 金额缺口计算：目标剩余 / 转化率 - 现有商机预估贡献

## 九、与核心业务模型的一致性检查

| 检查项 | 状态 |

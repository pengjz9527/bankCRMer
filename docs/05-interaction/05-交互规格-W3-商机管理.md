> **定位**：Block 3 "商机看板"的深度交互 + W3 商机管理页面的完整设计。承载三来源商机的展示、筛选、跟进，以及"生成作战包"的入口契约。
>
> **前置依赖**：W1 首页交互规格（已定义 Block 3 展示层和跳转映射）、核心业务设计模型（商机三来源、商机→作战包→商机待办链路）

> **页面范围**：
> - Block 3 商机看板（首页内深度交互，含目标进度计算逻辑）
> - W3 商机管理页（全屏独立页面，从 Block 3 [详情 ›] 进入）
>
> **版本**：v1.0 | **最后更新**：2026-07-15

## 二、Block 3 目标进度区深度交互

### 2.1 目标进度计算逻辑

```
AUM 净增目标（本月）：200 万
当前 AUM 净增：128 万
剩余缺口：200 - 128 = 72 万
────────────────────────────────────
设定转化率：15%（商机 → 实际 AUM 转化）
所需商机总数：72 / 15% / 每个商机平均价值 ≈ 12 个

当前已有商机：5 个
预计贡献：45 万（当前商机的预估价值之和）
商机缺口：12 - 5 = 7 个
金额缺口：72 - 45 = 27 万
```

### 2.2 进度条交互

| 触发 | 行为 |
|------|------|
| 点击进度条 | 展开详细指标浮层：理财销售 85/120万(71%)、基金销售 32/50万(64%)、新增客户 12/20户(60%) |
| 点击转化率数字 | 展开转化率说明："基于您过去 3 个月的商机→AUM 实际转化率计算" |

### 2.3 缺口警告逻辑

| 条件 | 展示 |
|------|------|
| 金额缺口 ≤ 0 | 绿色：当前商机预估贡献已覆盖目标 |
| 金额缺口 > 0 且商机数缺口 > 0 | 橙色警告：显示缺口金额 + "需获取 N 个商机" |
| 金额缺口 > 0 且管户基数不足 | 红色警告：显示缺口 + 触发 Block 4 新客拓展 |

## 三、Block 3 页签一：「当前商机」

### 3.1 统计栏

三个 `pool-stat` 并排显示。金额缺口栏使用 `pool-stat--warn` 样式（金色边框 + 暖色背景）。

| 统计项 | 计算方式 |
|------|------|
| 当前商机 | 三来源商机总数（系统推送 + AI 挖掘 + 客户经理创建） |
| 预计贡献 | 所有商机预估价值之和 |
| 金额缺口 | max(0, 目标剩余 / 转化率 - 预计贡献) × 平均商机价值 |

### 3.2 商机列表（简要模式）

每行一条商机，按预估价值降序排列：

| 字段 | 说明 |
|------|------|
| 来源图标 | 📥 系统推送 / 🤖 AI 挖掘 / 📝 客户经理创建 |
| 商机名称 | 简称（如"代发即将到账"） |
| 关键摘要 | 客户数 + 核心指标（如"2位 · 月均代发 3.2万"） |
| 预估价值 | 该商机的预估 AUM 贡献金额 |
| 操作文字 | `跟进 ›`（普通）/ `紧急 ›`（红色，流失预警专用） |

### 3.3 列表交互

| 触发 | 行为 |
|------|------|
| 点击某行 | 跳转 W3 商机管理页，自动定位到对应 Tab |
| 点击 [跟进 ›] | 进入该商机的详情面板 → [生成作战包] |
| 点击 [紧急 ›] | 同上，但面板顶部显示红色流失警告 |

## 四、Block 3 页签二：「商机挖掘」

### 4.1 显示条件

- **显示**：商机缺口 > 0（当前商机预估不足以覆盖目标）
- **隐藏**：商机缺口 ≤ 0（商机充足，无需挖掘）

### 4.2 挖掘方向列表

AI 扫描全量管户后，列出可挖掘方向。每项含：

| 字段 | 示例 |
|------|------|
| 挖掘方向 | 沉睡客户激活（238 位中识别） |
| 预计产出 | +5 个商机 |

列表底部显示合计和 [一键 AI 挖掘] 按钮。

### 4.3 挖掘流程

```
点击 [一键 AI 挖掘]
     ↓
按钮变为 "AI 挖掘中..." + 旋转加载图标
     ↓（后台异步处理，预计 10-30 秒）
TOAST 提示："AI 挖掘完成，发现 8 个新商机"
     ↓
页签自动切换到「当前商机」
     ↓
新增商机出现在列表中，标注 🤖 AI 来源 + 置信度
```

### 4.4 挖掘结果卡片

AI 挖掘的商机卡片需额外展示：

| 字段 | 说明 |
|------|------|
| 置信度 | 进度条，如 `████████░░ 82%` |
| 推理说明 | 一句话解释 AI 为何判断这是一个商机 |
| 操作 | [查看详情] [生成作战包] |

## 六、作战包生成入口契约

> **这是 W3 与 P1（第四步）之间的关键契约**。W3 负责触发，P1 负责呈现。

### 6.1 触发流程

```
W3 商机管理页
     │
     ├── 点击 [生成作战包]（商机卡片上）
     │        │
     │        ▼
     │        │
     │        ▼
     │   AI 生成作战包（后台 3-5 秒）
     │        │
     │        ├── 同步创建商机待办 🟣
     │        ├── 商机状态 → "已生成作战包，待触达"
     │        └── 跳转 P1 作战包首页
     │
     └── 点击 [查看画像] → 跳转客户画像页
```

### 6.2 传递给 P1 的数据

| 字段 | 说明 |
|------|------|
| 商机 ID | 用于回写商机状态 |
| 客户 ID | 关联客户画像 |
| 作战包模式 | 标准版 |
| 商机类型 | 代发到账 / 流失预警 / AI 挖掘 / 客户经理创建 |
| 商机关联数据 | 代发金额 / 流失概率 / AI 推理说明 / 意向描述 |

### 6.3 状态变更

| 事件 | 商机状态 |
|------|------|
| 点击 [生成作战包] → 确认 | 待跟进 → 已生成作战包，待触达 |
| 作战包过期（7天未使用） | 已生成作战包 → 待跟进（回退） |
| 商机待办执行完成 | 已生成作战包 → 已触达，待结果 |

# 客户画像与洞察应用设计方案

> 版本: v1.0  
> 日期: 2026-07-18  
> 关联文件: `prototype/workbench.html`

---

## 一、概述

客户画像（Customer Profile）与客户洞察（Customer Insight）是展业 APP 中两个核心的客户信息服务，分别服务于客户经理在不同场景下的信息获取与决策需求。两者在定位、数据性质、使用场景上存在明确边界，本方案旨在定义这一边界并规范两者的协同关系。

---

## 二、服务定位与价值边界

### 2.1 一句话定义

| 服务 | 定义 | 核心问题 |
|------|------|---------|
| **客户画像** | 客户全维度事实数据的结构化陈列 | 这位客户是谁？ |
| **客户洞察** | AI 对客户数据进行二次加工后的分析简报 | 这位客户正在发生什么变化？我该做什么？ |

### 2.2 价值主张

**客户画像 = 事实字典（What）**

- 客户经理接到客户时需要了解的基本信息，一步到位
- 需要查找某条具体数据（社保基数、上次联络内容）时的精确查询
- 从客户详情出发，执行下一步操作（创建商机、生成作战包）的操作枢纽

**客户洞察 = 分析简报（So What & Now What）**

- 管户 200+ 时快速筛选出需要关注的客户（信号徽标）
- 打开后 5 秒内判断客户当前状况（Hero 摘要 + 核心指标）
- AI 发现异常/机会 + 建议行动方案

### 2.3 差异特性

| 维度 | 客户画像 | 客户洞察 |
|------|---------|---------|
| **定位** | 结构化事实档案 | AI 分析报告 |
| **数据来源** | 原始业务数据（API 分段实时查询） | AI Agent 批量生成（T+1 快照入库） |
| **生成方式** | 实时查询 + 静态 fallback | 定时（每周）+ 按需触发 |
| **时效性** | 实时 | 快照（7 天有效） |
| **信息粒度** | 字段级（字段名 + 字段值） | 卡片级（标签/信号/建议） |
| **布局风格** | 折叠面板（完整浏览） | 卡片流（快速扫描） |
| **操作入口** | ✅ 拨号/微信/待办/商机/作战包 | 查看完整画像 |
| **独有内容** | 经营/信贷/社保/代发/交互/产品清单/权益 | AI 摘要/变化信号/风险信号/操作建议 |

## 三、数据结构与渲染架构

### 3.1 客户画像（10 个数据域）

```
renderW8DetailContent(name, p, custId)
├── Section 1: 基础信息（默认展开）
│   └── 姓名/性别/年龄/职业/行业/城市/学历/等级/风险/管户关系
├── Section 2: 家庭结构
│   └── 婚姻状况/子女情况/子女阶段
├── Section 3: 经营信息（仅企业主）
│   └── 经营主体/经营时长/持股比例/注册资金/经营地址/经营范围/经营性持续性
├── Section 4: 财富解读（默认展开）
│   ├── 净值分层：总资产/客户等级/客群标签
│   ├── 资金解读：年入金/入金来源/年出金/出金分布
│   ├── 持仓解读：持仓总规模/累计收益/年化收益率/近年峰值
│   └── 资产网格：存款/理财/基金/贵金属/保险（绝对值）
├── Section 5: 信贷解读
│   ├── 贷款记录
│   ├── 历史被拒
│   └── 社保/公积金缴存基数
├── Section 6: 行为标签（事实数据）
│   ├── 风险测评：风测结果
│   ├── 营销偏好：渠道/近3月活动/最佳联系时段
│   └── 工资代发：当月代发/近6月月均/峰值/薪资等级/3日留存/7日留存
├── Section 7: 商机与待办（默认展开）
│   └── 关联商机列表 + 作战包操作入口
├── Section 8: 最近交互
│   └── 沟通时间线
├── Section 9: 持有产品
│   └── 产品清单
└── Section 10: 权益与活动（默认展开）
    ├── 待领取奖励
    ├── 可用权益
    └── 可参与活动
```

### 3.2 客户洞察（8 个卡片区块）

```
buildInsightDetailHTML(custName, d)
├── Card 1: Hero 卡片（精简）
│   ├── 客户姓名
│   ├── 风险评级徽标（green/yellow/orange/red）
│   ├── 资产风格标签
│   └── AI 一句摘要
├── Card 2: 核心指标（四宫格）
│   ├── 总资产 (AUM)
│   ├── 近30天活跃度 + 互动标签 + 上次联络
│   ├── 风险评级 + 匹配状态
│   └── 关联商机数 + 估值
├── Card 3: 资产配置面板
│   ├── 配置总规模
│   ├── 四类资产比例条（存款/理财/基金/保险）
│   └── 近期到期产品提醒
├── Card 4: 家庭 + 收入双栏
│   ├── 家庭：生命周期阶段/婚姻/子女/财务需求标签
│   └── 收入：月均入账/月均支出/收入模式/代发/大额交易
├── Card 5: 行为偏好
│   ├── 浏览偏好标签
│   └── 产品兴趣标签
├── Card 6: 变化信号 🔔
│   ├── 信号数量
│   ├── 信号卡片（类型/标题/详情/严重度）
│   └── 建议操作（💡）
├── Card 7: 风险提示 ⚠️
│   ├── 风险数量
│   ├── 风险卡片（类型/标题/详情/级别）
│   └── 建议操作（💡）
└── Card 8: 底部
    ├── [查看完整画像 →] 按钮
    └── 元信息（生成时间/有效期）
```

### 3.3 内容重复已清零

重构前两服务存在 7 个字段重叠（基础信息、等级、风险、AUM、家庭、资产结构、行为偏好）。重构后：

- **画像**剥离所有 AI 分析/打标/信号内容，仅保留纯事实数据
- **洞察** Hero 卡片移除等级徽标（画像已有），保留核心上下文用于信号解读
- 通过互跳按钮形成「事实 → 分析」信息流，无需在洞察中重复展示基础事实

## 四、互跳交互设计

### 4.1 画像 → 洞察

```
┌─────────────────────────────────────┐
│  客户画像 · 王建国                    │
│  ┌─────────────────────────────────┐ │
│  │ ▼ 基础信息                       │ │
│  │ ▼ 财富解读                       │ │
│  │ ▼ 行为标签                       │ │
│  │ ...                             │ │
│  └─────────────────────────────────┘ │
│  ┌─────────────────────────────────┐ │
│  │ [拨号] [微信] [＋添加待办]        │ │
│  │ [创建商机] [🤖 AI 洞察]          │ │
│  └─────────────────────────────────┘ │
└─────────────────────────────────────┘
         │ 点击 [AI 洞察]
         ▼
┌─────────────────────────────────────┐
│  客户洞察 · 王建国   [低风险]        │
│  "财富客户，资产配置合理，近期...     │
│  ┌──┬──┬──┬──┐                      │
│  │总│活│风│商│  核心指标             │
│  └──┴──┴──┴──┘                      │
│  🔔 变化信号 · 2 条                  │
│  ⚠️ 风险提示 · 1 条                  │
│  ┌─────────────────────────────────┐ │
│  │ [📋 查看完整画像]                │ │
│  └─────────────────────────────────┘ │
└─────────────────────────────────────┘
         │ 点击 [查看完整画像]
         ▼ 返回画像详情
```

### 4.2 互跳调用链路

| 方向 | 触发按钮 | 调用函数 | 参数 |
|------|---------|---------|------|
| 画像→洞察 | `[AI 洞察]` | `openInsightDetail(custId, name)` | `custId` = `cust.insightCustId \|\| cust.id` |
| 洞察→画像 | `[查看完整画像]` | `openW8Detail(name, 'tab')` | `name` = `basic.name \|\| custName` |

**注意**：`openInsightDetail` 需要 `custId`（洞察 API 专用 ID），而不是客户姓名。`renderW8DetailContent` 函数签名已升级为 `(name, p, custId)` 以传递此参数。

## 六、设计原则

1. **互补而非替代**：画像与洞察不包含重复内容，各自服务不同场景
2. **事实先在画像，分析只在洞察**：打标、评语、信号、建议都属于洞察范畴，画像仅陈列可验证的事实
3. **互跳不互斥**：两端均可一键跳转到对方，形成完整信息闭环
4. **画像实时，洞察快照**：画像数据按需实时查询；洞察由 AI 定时生成，标注生成时间与有效期
5. **敏感度分层**：洞察的风险评级（green→red）用于客户列表的注意力筛选；画像的风险等级（R1-R5）用于合规检查

# 交互规格 — W2 日程处理与调整

> **定位**：Block 2 "今日日程安排"的深度交互设计。涵盖日程卡片处理、日程调整、全部待办分类列表三个子模块。
>
> **前置依赖**：W1 首页交互规格（已定义 Block 2 的展示层和跳转契约）
>
> **设计约束**：待办、商机、作战包的交互链路以《核心业务设计模型-待办商机作战包.md》为权威依据。
>
> **面向页面**：本规格中的交互均发生在首页 Block 2 区域内（浮层/面板模式），不跳转独立页面。
>
> **版本**：v1.0 | **最后更新**：2026-07-15

---

## 一、模块总览

```
Block 2 今日日程安排
├── 2.1 日程卡片处理交互
│   ├── 普通待办：点击卡片 → 处理面板（半屏浮层）

│   ├── 完成动效：翻转/消隐 → 轮播自动前进

│   ├── 跳过/推迟：左滑快捷操作
```

## 二、模块 2.1：日程卡片处理交互

### 2.1.1 普通待办卡片 — 处理面板

**触发**：点击普通待办卡片（非商机待办）或卡片上的 [开始处理] 按钮。

**交互形式**：从底部滑入半屏处理面板（不离开首页上下文）。

```
┌──────────────────────────────────────────┐
│ （首页内容变暗，半透明遮罩）               │
│                                          │
├──────────────────────────────────────────┤  ← 遮罩上方
│ 处理面板                          [关闭]   │

│ 3位客户产品到期，金额合计80万              │
│                                          │
│ ── 客户列表 ──────────────────────────   │
│                                          │

│ └──────────────────────────────────────┘ │
│                                          │
│ ┌──────────────────────────────────────┐ │
│ │ ○ 赵明辉 · 男 · 52岁 · 制造业         │ │

│ │   📞 电话  ✉️ 微信  ✓ 标记完成       │ │
│ └──────────────────────────────────────┘ │
│                                          │

```

#### 处理面板交互元素

| 元素 | 行为 |
|------|------|
| 📞 电话 | 记录为"电话联系"方式处理 → 标记该客户完成 |
| ✉️ 微信 | 记录为"微信联系"方式处理 → 标记该客户完成 |
| ✓ 标记完成 | 直接标记该客户已完成（无指定触达方式） |
| [全部标记完成] | 一键标记该任务下所有客户为已完成 |
| [查看客户画像] | 跳转到该客户画像详情页 |
| [标记为商机] | 弹出商机创建浮层 → 填写意向描述/预估金额 → 创建商机（来源二）→ 可选生成作战包 |

#### 处理动效

| 步骤 | 动效 | 时长 |
|------|------|------|
| 点击操作按钮 | 按钮变为"处理中..."，背景变灰 | 即时 |
| 处理成功 | 按钮变为"✓ 已处理"绿色，客户行淡出 | 300ms |
| 该卡片所有客户处理完 | 面板自动关闭 → 首页该卡片翻转消隐 | 400ms |
| 轮播自动前进 | 轮播跳到下一张未处理卡片 | 350ms |

#### 处理结果回写

| 待办类型 | 完成后的系统动作 |
|------|------|
| 产品到期 | 标记为已处理，无后续 |
| 大额异动 | 标记为已处理，无后续 |
| 贷款逾期 | 标记为已处理，无后续 |
| 生日提醒 | 标记为已处理，无后续 |
| 联络超期 | 更新最后联络日期，无后续 |
| 信用卡待办 | 标记为已处理，无后续 |

> **设计约束**：普通待办完成后无回写，不产生商机状态变更。如需创建商机，使用 [标记为商机] 入口。

### 2.1.2 商机待办卡片 — 跳转作战包

**触发**：点击商机待办卡片（带 🟣📋 标识）。

**行为**：不弹出处理面板，直接跳转到 P1 作战包首页。

| 元素 | 行为 | 跳转目标 |
|------|------|------|
| 点击卡片 | 跳转到该商机关联的作战包 | P1 作战包首页 |
| 点击 [查看作战包] | 同上 | P1 |
| 左滑 | [推迟拜访] [取消拜访] | 影响商机状态 |

> **说明**：商机待办的完整处理流程在第四步 P1-P9 中设计。此处仅定义从 Block 2 到 P1 的跳转契约。

### 2.1.3 完成动效与轮播衔接

```
处理面板关闭
     ↓
卡片翻转/消隐动效（400ms）
     ↓
┌──────────────────────────────────────┐
│ 该卡片变为半透明 + "✓ 已完成"水印     │
│ 上方出现 TOAST："产品到期 · 3位客户已处理" │
└──────────────────────────────────────┘
     ↓

     ↓
如果所有卡片处理完毕：
┌──────────────────────────────────────┐
│ 轮播区替换为：                         │
│ "🎉 今日待办已全部完成"                │
│ "AI 已生成明日工作计划建议"            │
│ [查看明日计划]                         │
└──────────────────────────────────────┘
```

## 三、模块 2.2：日程调整逻辑

### 3.1 调整入口与激活态

| 入口 | 位置 | 行为 |
|------|------|------|
| Block 2 标题栏 [调整日程] | section-header 右侧 | 激活日程调整模式 |
| Block 1 AI 浮层 [调整排程] | AI 排程详情浮层底部 | 滚动到 Block 2 + 激活调整模式 |
| 长按卡片 | 轮播中任意卡片 | 激活调整模式 + 当前卡片进入可拖拽态 |

**激活态视觉**：Block 2 区域边框变为蓝色虚线，每张卡片左上角出现拖拽手柄（⠿），时间标签变为可编辑态。

```
┌──────────────────────────────────────────┐
│ 📋 今日日程安排        [完成调整] [取消]   │  ← 模式切换
├──────────────────────────────────────────┤
│                                          │
│ ┌────────────────────────────────────┐  │
│ │ ⠿ ☀️ 上午 [#1] 产品到期             │  │  ← 拖拽手柄
│ │ 3位客户产品到期，金额合计80万         │  │
│ │ 🕐 [09:00▼] - [10:30▼] 约1.5h      │  │  ← 可编辑时间
│ │ ────────────────────────────────── │  │
│ │ 左滑选项：[推迟到明天] [今天不处理]    │  │
│ └────────────────────────────────────┘  │
│                                          │
│ ...（其余卡片同理）                       │
│                                          │
│ ⚡ AI 建议：调整后预计总耗时 3.2小时       │  ← 实时反馈
│                                          │
└──────────────────────────────────────────┘
```

### 3.2 调整时段（拖拽）

| 操作 | 行为 |
|------|------|
| 长按卡片拖拽手柄 | 卡片浮起（阴影加深），跟随手指移动 |
| 向上拖拽 | 卡片序号减小（往前排），上方卡片自动下移 |
| 向下拖拽 | 卡片序号增大（往后排） |
| 松手 | 卡片落位，AI 实时重算各卡片建议时间段 |
| 跨越上下午 | 拖到"上午/下午"分隔线另一侧时，时段标签自动切换（☀️↔🌤） |

**视觉反馈**：
- 拖拽中：目标位置出现蓝色插入线
- 落位后：所有受影响卡片的时间段闪烁更新（300ms 高亮）

### 3.3 修改时间（时间选择器）

| 操作 | 行为 |
|------|------|
| 点击时间标签 | 弹出时间滚轮选择器（iOS 风格） |
| 修改开始时间 | 结束时间 = 开始时间 + 预计耗时（自动计算） |
| 修改预计耗时 | 从预设选项中选择：15min / 30min / 45min / 1h / 1.5h / 2h |
| 确认 | 时间更新，AI 检查是否与相邻卡片冲突 |

**时间冲突检测**：
- 如果新时间与前后卡片重叠 → Toast 提示"与 #N 任务时间冲突，已自动后移"
- AI 自动调整后续卡片时间，避免重叠

### 3.4 跳过/推迟（左滑快捷操作）

```
在任意卡片上左滑（非调整模式也可以触发）
        ↓
┌──────────────────────────────────┐
│ [推迟到今天晚些时候]               │  ← 移到最后一张
│ [推迟到明天]                      │  ← 从今日清单移除，加入明日
│ [今天不处理]                      │  ← 从今日清单移除，保留在待办池
│ [取消]                           │
└──────────────────────────────────┘
```

| 选项 | 行为 | 持久化 |
|------|------|------|
| 推迟到今天晚些时候 | 卡片移到轮播末尾，时间段重新分配 | 当日有效 |
| 推迟到明天 | 卡片从 Block 2 移除，加入明日待办清单 | 跨日保留 |
| 今天不处理 | 卡片从 Block 2 移除，回到"全部待办"池 | 保留在待办池 |

### 3.5 AI 重新排程

**触发条件**：任何手动调整（拖拽/改时间/跳过）后自动触发。

**AI 重算逻辑**：

| 输入 | 处理 |
|------|------|
| 当前卡片顺序 + 时间段 | 视为用户意图的"锚点" |
| 被跳过的卡片 | 从今日排程移除 |
| 剩余待办的预计耗时 | 重新计算总耗时 |
| 时间冲突 | 按优先级自动后移低优先级任务 |
| 优先级规则 | 产品到期 > 大额异动 > 贷款逾期 > 商机待办 > 生日提醒 > 联络超期 > 信用卡待办 |

**反馈形式**：
- Block 2 底部出现蓝色提示条："AI 已根据您的调整重新排程，总耗时 3.2 小时"
- 受影响卡片的时间段数字闪烁更新
- 3 秒后提示条自动消失

### 3.6 持久化规则

| 调整类型 | 持久化范围 |
|------|------|
| 卡片排序 | 当日有效，次日以 AI 排程为基准重新生成 |
| 时间修改 | 当日有效 |
| 推迟到明天 | 跨日保留，明日待办清单中出现 |
| 今天不处理 | 保留在全部待办池，次日可能重新排入 |
| 处理完成 | 永久标记，不再出现 |

> **关键设计**：每日 AI 排程 = 全新基准。客户经理的手动调整仅当日有效，次日 AI 根据最新待办清单重新生成排程。这避免了"明天的日程被昨天的临时调整锁死"的问题。

### 4.4 分组交互

| 操作 | 行为 |
|------|------|
| 点击分组标题行 | 展开/折叠该组 |
| 点击客户行 | 弹出处理浮层（同 2.1.1 处理面板，仅该客户一条） |
| [全部标记完成] | 仅在该组展开时显示，一键处理该组所有客户 |
| [仅看未处理] 开关 | 过滤掉已完成的分组和客户，只显示未处理项 |

### 4.5 处理完毕的视觉

- 已处理客户行：灰色文字 + 删除线
- 整组处理完毕：分组标题前 ✓ 绿色勾
- 全部处理完毕：顶部显示"🎉 全部待办已完成" + 返回工作台按钮

### 4.6 与 Block 2 轮播的同步

| 事件 | 分类列表行为 | Block 2 轮播行为 |
|------|------|------|
| 在分类列表中处理了某客户 | 该行标记已完成 | 对应卡片人数减 1 或移除 |
| 在分类列表中处理了一整组 | 该组标记已完成 | 对应卡片从轮播中移除 |
| 关闭分类列表 | 返回首页 | 轮播数据刷新（移除已处理卡片） |
